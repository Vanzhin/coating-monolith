# Подбор систем: точный минимум по маркировке — дизайн

**Дата:** 2026-10-26
**Контекст:** Coatings, поиск систем покрытий (`/cabinet/coating/coating-system/list`).

## Зачем (intent)

Инженер подбирает систему под конкретную задачу с требованием «стандарт + категория/степень + долговечность/условия». Переспек (система, сертифицированная на более жёсткую категорию или бо́льшую долговечность) физически подходит, но это **лишние слои и деньги**. Нужен **минимально достаточный** вариант.

Сейчас подбор отдаёт переспек: на запрос ISO 12944 / C3 / HIGH возвращается система с потолком C4-VH и CX-H, потому что фильтр раскрывает запрос «вверх» (C3 → {C3,C4,C5,CX}, HIGH → {HIGH,VERY_HIGH}) и ловит любую перекрывающую. Матч корректен по домену (система реально перекрывает C3-H), но это не то, что нужно инженеру.

## Правило

Система попадает в выдачу по запросу «стандарт + первая ось + вторая ось», только если у неё есть сохранённое соответствие с **ровно той же** первой осью и **ровно той же** второй осью. Никакого раскрытия «вверх».

- ISO 12944: категория коррозивности — точно; долговечность — точно.
- СП 28: степень агрессивности — точно; условия эксплуатации — точно (и сейчас номинальные/точные).
- Вторая ось применяется только там, где она есть: у ISO CX/Im4 оси долговечности нет (`hasSecondaryAxis` = false), залипший в URL `durability` игнорируется — как и сейчас.

## Почему не трогаем данные/проекцию

Проекция `coating_system_compliance` уже хранит только **потолочные** пары системы:

- ISO: `Iso12944Matches::strongestOnly()` сворачивает набор до недоминируемых максимумов.
- СП: `Sp28Evaluator` пишет по одной сильнейшей достижимой степени на каждое условие.

Значит «потолок == запрос» и есть «минимально достаточная система». Переход на точный матч — это снятие раскрытия в фильтре, и всё. Проекцию, оценщики, свёртку не трогаем (они по-прежнему нужны, чтобы потолок считался).

## Решение по охвату (моя калька, на ревью можно зарубить)

Правило применяется **единообразно ко всем стандартам** с упорядоченными осями (ISO + СП), а не только к ISO. Иначе один стандарт режет переспек, другой нет — поведение подбора становится непредсказуемым.

## Non-goals / anti-goals

- **Пустая выдача — штатный исход.** Если точного минимума в каталоге нет, показываем пусто. Никаких подсказок «точного нет, есть сильнее», никакого фолбэка на переспек. (Подтверждено заказчиком.)
- Не добавляем переключатель «показать и сильнее».
- Не меняем схему БД, проектор, оценщики, свёртку `strongestOnly`, ранги enum-ов (`rank()`/`family()` остаются — на них держится вычисление потолка).
- UX-водопад (после выбора стандарта сразу открывать обе оси) — **отдельная задача**, в этот дизайн не входит.

## Затронутая механика (как есть сейчас)

- `CoatingSystemFinder::applyCompliance` — единственный потребитель раскрытия; строит `csc.category IN (expandPrimary)` / `csc.durability IN (expandSecondary)`.
- `StandardFacets::expandPrimary/expandSecondary` (+ реализации `Iso12944Facets`, `Sp28Facets`) — «≥»-раскрытие; после перехода на точный матч становятся мёртвыми.
- Enum-хелперы `IsoCorrosivityCategory::atOrAboveInFamily()`, `IsoDurability::atOrAbove()`, `SpAggressivity::atOrAbove()` — зовутся только из этих `expand*`; тоже мёртвые.

## Крайние случаи

- Запрос только категории (без долговечности) → точная категория, любая долговечность этой категории.
- Запрос только долговечности (без категории) → точная долговечность, любая категория (как и сейчас при `category === null`).
- CX/Im4 + `durability` в URL → долговечность игнорируется (нет второй оси).
- Неизвестный стандарт / `facetsFor` == null → `1 = 0`, пустая выдача (без изменений).
