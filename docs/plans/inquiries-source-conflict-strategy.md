# План (бэклог, v3 извлечения): Inquiries — расхождение значений между телом и вложением

Отдельная задача улучшения качества извлечения. Делать ПОСЛЕ текущей ветки (живой подбор + промпт v2). Движок/веб не меняются концептуально — работа в ассемблере текста + промпте + одном новом поле извлечения.

## Проблема

Сейчас `FileTextInquiryAssembler` склеивает тело запроса + извлечённый текст КАЖДОГО вложения в один блоб через `\n\n`, **без меток источника**. LLM извлекает из объединения. При расхождении значений (напр. тело: «нефть 90 °C», вложение-опросник: «нефть 80 °C») модель **молча выбирает одно** — непредсказуемо, может ошибиться, инженер об этом не узнаёт.

Для подбора ЗАЩИТНОГО покрытия тихий неверный выбор опасен (не та температура/среда → не та защита).

## Стратегия (решено): вариант 3 + приоритет

**Не молчать: подсветить расхождение И взять приоритетный источник.** Безопаснее всего — инженер видит конфликт и при необходимости правит через «Исправить параметры».

Три части:

1. **Разметить источники в склейке.** Вместо голого `\n\n` — помечать провенанс каждого куска:
   ```
   === Тело письма ===
   <тело>

   === Вложение: 0001-П-ОЛ.pdf ===
   <текст вложения>
   ```
   Чтобы модель знала, ОТКУДА значение, и могла сравнивать (сейчас она к источнику слепа).

2. **Правило приоритета в промпте.** При расхождении значения между источниками — какой главнее.
   - **РЕШЕНО (2026-10-29): приоритет у ВЛОЖЕНИЯ** (формальное ТЗ/опросник — источник истины, тело = сопроводиловка). Тело и вложение спорят → берём вложение.
   - Спор ВНУТРИ одного источника (оба значения в теле, как в примере «90 в начале, 80 в конце», или оба в одном вложении) → берём более жёсткое/консервативное для подбора (выше температура, строже категория/срок).

3. **Подсветка расхождения инженеру.** Модель при конфликте значения (температура / вещество / среда / подложка / категория / срок) добавляет пометку: «температура: в теле 90, во вложении 80 — взял 80 (приоритет вложения)». Механизм: новое поле извлечения `conflicts: []` (строки) → процессор дописывает их в `warnings` агрегата → видно на карточке в блоке предупреждений. Тот же механизм ловит и расхождение внутри одного источника (пример пользователя: две разные температуры в теле).

## Что меняется

- `FileTextInquiryAssembler::assemble` — метки источника вокруг каждого куска (`=== Тело письма ===` / `=== Вложение: <имя> ===`). Пустые/нечитаемые вложения — как сейчас (предупреждение). СДЕЛАНО.
- `system-prompt.v3.txt` + `SystemPromptBuilder::VERSION='v3'` — (а) текст размечен источниками; (б) приоритет вложения + правило «спор внутри источника → консервативнее»; (в) инструкция эмитить `conflicts` при расхождении + поле `conflicts` в схеме. СДЕЛАНО.
- `ExtractionResult` + парсер ответа — новое поле `conflicts` (list<string>). СДЕЛАНО (поле живёт на результате извлечения, не на `ExtractedParameters` — это провенанс извлечения, а не параметр фильтра).
- `SystemSelectionProcessor` — дописывает `$extraction->conflicts` в `warnings` (рядом с `dropped`). СДЕЛАНО (не маппер: маппер — про shape параметров, warnings собирает процессор).
- Прогон на стенде/воркере на реальном письме с расхождением (тело vs вложение) — ОСТАЛОСЬ.

## Кэш (на будущее)

`ApprovedParameterCache` сейчас заглушка (`NoopApprovedParameterCache`, всегда miss) — conflicts считаются каждый раз. Когда появится реальный кэш, попадание пропустит вызов модели и, значит, conflicts-заметки исходного извлечения. Решить в задаче кэша: либо кэш-запись несёт conflicts исходного прогона (тогда warnings не исчезают), либо осознанно их не показываем на кэш-хите (канон — параметры, не предупреждения). Пока не трогаем.

## Развилки

- Приоритет источника: ВЛОЖЕНИЕ (решено 2026-10-29).
- Что считать «ключевым значением» для подсветки (температуры/вещества/среда/подложка/стандарт) — калибровать на стенде.
- Промпт чувствительный (обкатан на реальных док) — менять аккуратно, не ломая v2-правила (ассей продукта не разбивать, пропарка только в search, «ориентир/запас» не брать). v3 = v2 + блоки про источники/расхождения + поле conflicts.

## Тесты

- Ассемблер — юнит round-trip: метки источника присутствуют, порядок тело→вложения.
- Промпт — только перегоном на стенде (LLM), юнит не ловит.
- Маппер — `conflicts` → warnings.
