# План (бэклог, v3 извлечения): Inquiries — расхождение значений между телом и вложением

Отдельная задача улучшения качества извлечения. Делать ПОСЛЕ текущей ветки (живой подбор + промпт v2). Движок/веб не меняются концептуально — работа в ассемблере текста + промпте + одном новом поле извлечения.

## Проблема

Сейчас `FileTextInquiryAssembler` склеивает тело запроса + извлечённый текст КАЖДОГО вложения в один блоб через `\n\n`, **без меток источника**. LLM извлекает из объединения. При расхождении значений (напр. тело: «нефть 90 °C», вложение-опросник: «нефть 80 °C») модель **молча выбирает одно** — непредсказуемо, может ошибиться, инженер об этом не узнаёт.

Для подбора ЗАЩИТНОГО покрытия тихий неверный выбор опасен (не та температура/среда → не та защита).

## Стратегия (решено): вариант 3 + приоритет

**Не молчать: подсветить расхождение И взять приоритетный источник.** Безопаснее всего — инженер видит конфликт и при необходимости правит через «Исправить параметры».

Три части:

1. **Разметить источники в склейке.** Вместо голого `\n\n` — помечать провенанс каждого куска:
   ```
   === Тело письма ===
   <тело>

   === Вложение: 0001-П-ОЛ.pdf ===
   <текст вложения>
   ```
   Чтобы модель знала, ОТКУДА значение, и могла сравнивать (сейчас она к источнику слепа).

2. **Правило приоритета в промпте.** При расхождении значения между источниками — какой главнее.
   - **РАЗВИЛКА (решить при реализации):** вложение (формальное ТЗ/опросник — источник истины, тело = сопроводиловка) ИЛИ тело (последнее слово человека: «в опроснике 80, но согласовали 90»). Рекомендация по умолчанию — **вложение приоритетнее для технических значений**, но подтвердить у пользователя.

3. **Подсветка расхождения инженеру.** Модель при конфликте ключевого значения (температура / вещество / среда / подложка) добавляет пометку: «расхождение: тело 90 °C / вложение 80 °C — взял N (приоритет: <источник>)». Механизм: новое поле извлечения `conflicts: []` (строки) → маппер переносит их в `warnings` агрегата → видно на карточке в блоке предупреждений.

## Что меняется

- `FileTextInquiryAssembler::assemble` — метки источника вокруг каждого куска (тело + имя вложения). Пустые/нечитаемые вложения — как сейчас (предупреждение).
- `system-prompt.v{N}.txt` → новая версия: (а) объяснить, что текст размечен источниками; (б) правило приоритета; (в) инструкция эмитить `conflicts` при расхождении ключевых значений. Бамп `SystemPromptBuilder::VERSION`.
- `ExtractedParameters` + парсер ответа — новое поле `conflicts` (list<string>).
- `SystemSelectionParameterMapper` — переносит `conflicts` в warnings (как сейчас нерезолв веществ).
- Прогон на стенде/воркере на реальном письме с расхождением (тело vs вложение).

## Развилки

- Приоритет источника: вложение / тело (см. п.2) — подтвердить у пользователя.
- Что считать «ключевым значением» для подсветки (температуры/вещества/среда/подложка/стандарт) — калибровать.
- Промпт чувствительный (обкатан на реальных док) — менять аккуратно, не ломая v2-правила (ассей продукта не разбивать, пропарка только в search, «ориентир/запас» не брать).

## Тесты

- Ассемблер — юнит round-trip: метки источника присутствуют, порядок тело→вложения.
- Промпт — только перегоном на стенде (LLM), юнит не ловит.
- Маппер — `conflicts` → warnings.
