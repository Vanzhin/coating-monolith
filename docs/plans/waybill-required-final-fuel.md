# Обязательный конечный остаток топлива в путевом листе

## Контекст и решение

Сейчас `Waybill::reviseDraftWithRefuelingOperations` вычисляет пустой конечный одометр по сумме поездок, но разрешает сохранить лист без топлива или с `Fuel.remaining = null`. Нужно, чтобы при сохранении черновика были заполнены конечный одометр и конечный остаток.

Согласовано: авторасчёт одометра сохранить. Поэтому новое правило касается конечного остатка: пустое значение запрещено, число `0` разрешено. После сохранения оба значения обязательны; ручной ввод одометра не становится обязательным.

Существующие записи с `remaining = null` должны по-прежнему загружаться и отображаться. Миграция и запрет `NULL` в `Fuel` не нужны: при следующем сохранении домен потребует заполнить значение. Проверка находится в домене, не в маппере или контроллере.

## Шаги

1. В `Waybill::reviseDraftWithRefuelingOperations` до мутации требовать `Fuel` и непустой `Fuel::remaining()`. Использовать существующее сообщение `Укажите остаток топлива на конец периода.` Убрать ставшие избыточными nullable-ветки после проверки, не меняя автоматический расчёт одометра и остальные инварианты. Неудачная ревизия не должна затирать ранее сохранённые значения агрегата.
2. Оставить `Fuel.remaining` nullable для загрузки старых записей и сериализации исторических данных. Не менять БД, DBAL-тип и чтение старых черновиков.
3. Обновить текст формы: убрать совет оставить конечный остаток пустым, указать обязательность и допустимость нуля. Подсказку автоматического расчёта одометра сохранить. Серверная ошибка должна повторно показывать форму со всеми введёнными данными.
4. Добавить доменные тесты: отказ без `Fuel`, отказ с `remaining = null`, принятие нулевого остатка, сохранение авторасчёта одометра. Заменить тесты, которые ранее специально разрешали сохранение без конечного остатка.
5. Добавить HTTP-проверки создания и редактирования: пустой остаток даёт 422, не создаёт/не изменяет лист и сохраняет введённые поля; нулевой остаток принимается. В успешных существующих сценариях передать корректный конечный остаток, не ослабляя проверки CSRF, конфликта версии, доступа и одометра. Тесты, где отказ происходит раньше новой проверки, не менять без необходимости.
6. Привести fixtures доменных и Application-тестов к новому инварианту: успешные вызовы `reviseDraft*` и create/update-команд получают конечный остаток. Маппер продолжает только преобразовывать пустую строку в отсутствующее значение для доменной проверки.
7. Обновить противоречащую формулировку в `docs/plans/waybill-single-create-form.md`. Старый общий `waybill.md` помечен устаревшим и остаётся историей.
