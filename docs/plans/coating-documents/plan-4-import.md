# План 4 — Импорт документов и систем из Excel «перечень заключений»

Общий контекст — `design.md`. Зависит от `plan-1-issuer.md`, `plan-2-document.md`
(агрегаты `Issuer`/`Document` существуют). Зеркалит существующий docx-импорт систем
(`docs/plans/import-coating-systems.md`, команда `app:coating-system:import`).

## Цель

Перенести заключения из `~/Downloads/1. перечень заключений Литум изм. 04.05.2026.xlsx`
в БД: на каждую запись — **создать новую систему** (не матчим существующие) и повесить на
неё **документ** (заключение), издателя резолвить/создавать по «автору».

## Решено (с пользователем)

- **Не матчим системы** (вариант б): на каждую запись создаём НОВУЮ `CoatingSystem` через
  `CreateCoatingSystemCommand`, затем `CreateDocumentCommand` со ссылкой на созданную систему.
- **Файлов PDF пока нет** — документы создаём без файла (`file = null`).
- **Издатель** — резолв/создание `Issuer` по колонке «автор».
- **Форма** — консольная команда + нормализованный JSON-интермедиат (xlsx на PHP не парсим).
- **Импортируем только лист «общий список»** (см. находку ниже — тематические листы это его
  подмножества).

## Находки (изучено автономно)

### Листы — тематические это подмножества мастера (вопрос 3 решён данными)
12 листов; «общий список» — 101 уникальное заключение (110 строк-групп). Все тематические листы
(«Наружка», «c ОГЗ», «Бетон», «Внутрянка», «Минудобр-метанол», «Im…», «Температуры», «РжД»,
«Дезактив атом», «отдельные испыт.») — их номера заключений ПОЛНОСТЬЮ входят в мастер, кроме
одного: `ТС-НИГАЗ-22-334-2` в «Наружке» (нет в мастере — вероятно опечатка от `ТС-НМГАЗ-…`).
Вывод: импортируем мастер, тематические игнорируем; аномалию — проверить вручную.

### Структура строк мастера
Одна система/заключение = 1+ строк. Метаданные (автор, год, «точная дата»=Excel-serial, № закл.,
тип испытаний, «срок экспл./среда», примечания, общ. толщина) — на ПЕРВОЙ строке группы (там, где
непустой «автор»). Далее строки без «автора» с материалом = доп. слои. Колонка «слои» («1-2»/«1»/«2»)
+ «толщины слоёв» («2х125»/«240»/«60-80») задают число слоёв и ТСП. Парсер (scratchpad
`parse_master.py`) даёт **110 документов**, каждый с `layers: [{material, dft}]`.

### Материалы: 37 различных
Включая альтернативы через «/» (`Литакоут Фрост/Флекси`, `Литакоут Классик/Фрост/Фрост У`,
`Литамастик 290/190`) — резолвить как в docx-импорте (первая альтернатива, что есть в БД).

### Записи без толщины (4) → blocked
`Литатанк Стронг` (автоклав), `Литамастик Универсал 20` (пропарка), 2×`Литакоут Эпокс` — ТСП пуст.
Слой с null-ТСП не создать (`CreateCoatingSystemCommand` требует int dft) → `blocked` + отчёт.

## Гэпы / открытые развилки (нужны решения пользователя)

1. **Цвет слоя.** По домену цвет ОПЦИОНАЛЕН (`CoatingSystemLayer`: null-цвет валиден; инвариант
   срабатывает только если цвет задан — тогда он должен быть из `getPossibleColors()` покрытия
   или покрытие `isTintable()`). docx-импорт создал 95 систем БЕЗ цветов. В Excel цветов слоёв НЕТ.
   Развилка:
   - **A** — импорт без цветов слоёв (просто, работает как docx-импорт).
   - **B** — требовать цвет (правило пользователя). Тогда решить: какому слою (всем/только финишу),
     какой цвет брать (в файле нет — дефолтный/первый из `getPossibleColors`?), и репортить покрытия
     без цвета+блеска (`getGloss()` nullable) как «дополнить».
2. **Подложка / среда / подготовка.** В Excel их НЕТ, а `CreateCoatingSystemCommand` требует
   `substrate` + `environment` + `surfaceTreatmentId`. docx-импорт брал их из заголовков секций
   (запечены в JSON). Здесь заголовков нет. Развилка: дефолт (`steel_carbon` + `atmospheric` + `Sa 2½`)
   или вывод из «тип испытаний»/«срок экспл./среда» (напр. «метанол/пропарка»→immersion/special,
   «С5»→atmospheric, ОГЗ→special)? По умолчанию — дефолт, флажки `--substrate`/`--environment`.
3. **Резолв материала → покрытие**: нормализация имени + альтернативы через «/»; ненайденное →
   `blocked` + отчёт (как docx-импорт). Список 37 материалов — свериться с БД при dry-run.
4. **Дедуп/идемпотентность**: по № заключения (`title` документа) — не создавать дубль. Но т.к. на
   каждую запись создаём НОВУЮ систему — повторный прогон создаст дубли систем; нужен маркер
   «уже импортировано» (по № заключения) → пропуск.

## Маппинг колонок Excel → поля

| Excel | Поле |
|---|---|
| № закл./протокола | `Document.title` |
| автор | `Issuer` (резолв/создание) → `Document.issuerId` |
| точная дата (Excel-serial) | `Document.issuedAt` (конверсия serial→дата) |
| «срок действия до …» (из примечаний) | `Document.expiresAt` (парсинг даты) |
| срок экспл., среда | `Document.subject` |
| тип испытаний + прочие примечания | `Document.description` (склейка) |
| — (нет в файле) | `Document.testStandard` = null (или из примечаний, если явно ГОСТ/СП) |
| материалы + толщины | слои создаваемой `CoatingSystem` |
| вид документа | `DocumentKind::Conclusion` по умолчанию (в мастере всё «заключения») |

## Реализовано

Решения: **A** (без цветов слоёв); подложка — «бетон» в столбце K → concrete, иначе steel_carbon+Sa 2½;
среда — `special` (пропарка/автоклав/термостойк/температур/криоген), `immersion` (метанол/нефт/мазут/
морск/вода/погруж), иначе `atmospheric`. Подложка/среда/даты запечены в JSON при парсинге.

Размещение — в **Coatings/Infrastructure/Console** (Coatings→Certificates, консистентно с guard;
Certificates не тянет Coatings). Файлы:
- `app/src/Coatings/Infrastructure/Console/Resources/conclusions.json` — 110 записей, КОММИТИМ как
  источник истины (сам разовый python-скрипт парсинга из листа «общий список» — вне репо).
- `app/src/Coatings/Infrastructure/Console/ImportConclusionsCommand.php` — команда
  `app:certificates:import-conclusions` (`--file`, `--dry-run`). На запись: резолв/создание `Issuer`
  по автору → `CreateCoatingSystemCommand` (новая система) → `CreateDocumentCommand` (заключение,
  ссылка на систему). Резолв материала/подготовки — как docx-импорт (`ImportSupport`). Дедуп по
  названию системы (`Система (закл. N)`). Отчёт: created/skipped/blocked(нет покрытия/ТСП)/failed.
- Тест: `tests/Functional/Coatings/Infrastructure/Console/ImportConclusionsCommandTest.php` — happy-path
  через фикстуру (реальное покрытие+подготовка → создаётся система+документ+издатель).

Smoke `--dry-run` в тест-стеке (пустой БД): команда исполняется, обрабатывает все 110 записей.

## Следующий шаг (пользователь, на dev-БД)
- `./run console app:certificates:import-conclusions --dry-run` — увидеть реальные created/blocked,
  список ненайденных из 37 материалов и покрытий без подходящей подготовки (бетон).
- Долить недостающие покрытия/подготовки, повторить dry-run; затем прогон без `--dry-run` (идемпотентно).

## Известные огрехи (проверить на данных)
- «авиатопливо (ТС-1)» по правилу среды → `atmospheric` (фактически погружение в топливо) — ключевого
  слова нет в списке; при желании добавить `топлив` в immersion и перегенерить JSON.
- Дубль № `ТС-НМГАЗ-22-334-12` (две строки) → две системы; при необходимости слить вручную.
- 1 аномалия `ТС-НИГАЗ-22-334-2` (только в «Наружке», не в мастере) — не импортируется; вероятная опечатка.
