# План 4 — Импорт документов и систем из Excel «перечень заключений»

ЗАГЛУШКА — детальный брейншторм отдельно. Общий контекст — `design.md`. Зависит от
`plan-1-issuer.md` и `plan-2-document.md` (агрегаты `Issuer`/`Document` существуют).

## Цель

Перенести данные из `~/Downloads/1. перечень заключений Литум изм. 04.05.2026.xlsx` в БД.
Для каждой строки: если такая система покрытий уже есть — создать документ и привязать к ней;
если системы нет — создать систему, затем документ. Издатели (`Issuer`) — резолв-или-создание
по названию из колонки «автор».

## Подход (предварительно, по образцу существующего импорта)

Зеркалим `docs/plans/import-coating-systems.md` (команда `app:coating-system:import`):
- xlsx на PHP не парсим — приводим к нормализованному JSON вне репо, JSON коммитим как источник
  истины импорта.
- Консольная команда читает JSON и по каждой строке:
  1. резолв/создание `Issuer` по названию;
  2. матчинг системы: если есть — берём её id; если нет — `CreateCoatingSystemCommand`
     (вся доменная валидация работает как есть), затем берём id созданной;
  3. `CreateDocumentCommand` (`ReferenceType::CoatingSystem` + id системы, поля из строки, файл — если есть).
- Резолв «материал из файла → покрытие в БД» — в PHP против живой БД (как в существующем импорте),
  чтобы повторный прогон подхватывал ранее заблокированные строки.
- Идемпотентность: по номеру заключения (`title`) + владельцу — не создавать дубль документа;
  по составу — не создавать дубль системы.

## Открытые вопросы (решить в брейншторме Плана 4)

1. **Критерий матчинга «такая система уже есть»** — по составу слоёв (покрытия+толщины) +
   подложка + подготовка + среда? Точное совпадение или нечёткое? Это самое сложное место.
2. **Ненайденный материал-`Coating`** — вероятно как в существующем импорте: `blocked` с причиной,
   прогон не падает, отчёт в конце.
3. **Файлы PDF** — есть ли сканы для импорта или только метаданные? Если сканы — откуда берём,
   как кладём в `document_scans`.
4. **Маппинг колонок Excel → поля `Document`** — «тип испытаний» (не заводим полем), «срок экспл.,
   среда» → `subject`, «прочие примечания» → куда (нет поля `notes`; в `description`?),
   «срок действия до …» → `expiresAt` (парсинг даты), «точная дата» (Excel-serial) → `issuedAt`.
5. **Листы Excel** — какие из 12 импортируем; лист «общий список» vs тематические (дубли?).
6. **Форма импорта** — консольная команда (предпочтительно, идемпотентно) vs Doctrine-миграция.
7. **Мульти-ссылки**: один документ теперь может ссылаться на несколько владельцев. Если одно и
   то же заключение (один номер) в Excel встречается для нескольких систем — сливать в ОДИН
   `Document` с несколькими `Reference` или создавать отдельные документы на каждую систему?
   (влияет на дедуп по номеру и на матчинг).

## Данные Excel (уже разобрано в брейншторме модели)

Колонки листа «общий список»: номер/тип системы; слои (материал, толщины, общ. толщина);
автор (лаборатория); дата (год); точная дата (Excel-serial); номер закл./протокола;
тип испытаний (стойкость/климатика/автоклав/пропарка); «срок экспл., среда»; прочие примечания
(в т.ч. «срок действия до …»). Лист «c ОГЗ» добавляет колонки коррозивностей С3/С4/С5/СХ/УХЛ1/ОМ
и огнезащитные системы (пример из запроса — R120).
