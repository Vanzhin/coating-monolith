# Inquiries, план 9: детерминизм извлечения — заземление температур + seed

Дата: 2026-10-29. Шаг 4 роадмапа `inquiries-accuracy-roadmap.md` («одинаковый вход → одинаковый выход»). Берём то, что без зависимостей от провайдера. `json_schema` и закрепление версии модели — ЗАПАРКОВАНЫ (нужна проверка возможностей NetAngels, см. ниже), их этим планом не делаем.

## Зачем

Две цели: (1) безопасность — поймать **выдуманную моделью температуру** (её нет в тексте), для защитного покрытия неверная T критична; (2) чуть больше повторяемости прогона через `seed`.

## Опора

- `NetAngelsExtractor::extract` уже шлёт `temperature: 0`, `response_format: json_object`. Сюда добавляем `seed`.
- `ExtractedParameters` несёт СЫРЫЕ температуры модели: `chemicalResistance.maxTemperature/peakTemperature`, `thermal.maxTemperature/peakTemperature`, `applicationMinTemp.from/to`. (`minApplicationTimeAt20` — минуты, НЕ температура.)
- `SystemSelectionProcessor` собирает `warnings` (сейчас: mapper warnings + conflicts + dropped). Сюда добавляем предупреждения заземления.
- Ассемблер (`FileTextInquiryAssembler`) даёт собранный текст (тело + вложения с метками) — против него и сверяем.

## Флоу

1. Процессор извлёк параметры (`$extraction = extractor->extract`) и собрал текст (`$assembled->text`).
2. **Заземление:** `TemperatureGroundingChecker->check($extraction->parameters, $assembled->text)` — для каждой НЕнулевой температуры из `ExtractedParameters` проверяет, встречается ли это число в тексте как отдельное число. Нет → предупреждение «Температура N °C (поле X) в тексте не найдена — возможно, выдумана моделью».
   - Сверяем **СЫРЫЕ** температуры модели (`ExtractedParameters`), НЕ маппленные: маппер может вывести производную (пик → лимит выживания), которой в тексте и не должно быть.
   - Направление только высокоточное: «модель вернула T, которой нет в тексте». Обратное («в тексте есть число, модель пропустила») не берём — шумно (в тексте много чисел).
   - Это **предупреждение, не отбрасывание**: значение не трогаем (текст мог перефразировать), инженер видит флаг и решает.
3. Процессор дописывает эти предупреждения в `warnings` рядом с conflicts/dropped.

Матчинг числа: ищем как отдельное число (границы цифр, опц. минус), чтобы `90` не совпало внутри `1908`. Число с °C/«градусов»/«+90»/«-10»/диапазоны `210÷230`/`40-60` — цифры всё равно присутствуют, матч срабатывает. Прописью («девяносто») — редкий ложный варнинг, приемлемо (это подсказка, не блок).

## seed

В теле запроса `NetAngelsExtractor` добавляем `'seed' => <фикс. константа>` (напр. `SEED = 7`). Незнакомое поле OpenAI-совместимый шлюз обычно игнорирует — хуже не будет; на поддерживающем бэкенде вместе с `temperature:0` даёт near-повторяемость. Константа задокументирована в классе.

## Что меняется

- Новый `App\Inquiries\Application\Service\TemperatureGroundingChecker` — `check(ExtractedParameters $p, string $text): list<string>`. Чистый, без зависимостей.
- `SystemSelectionProcessor` — инжектит checker, вызывает после извлечения, дописывает предупреждения.
- `NetAngelsExtractor` — добавляет `seed` в запрос (+ константа).

## Развилки (решены)

- Предупреждение, не отбрасывание. (решено)
- Только «модель → нет в тексте», обратное не делаем. (решено)
- Поля: chem max/peak, thermal max/peak, applicationMinTemp from/to. Минуты сборки — нет. (решено)
- `seed` — фиксированная константа. (решено)

## Запарковано (нужна проверка NetAngels)

- `response_format: json_schema` вместо `json_object` — убирает вариативность формы; только если шлюз поддерживает (иначе 400). Вслепую не включаем.
- Закрепление датированного снапшота модели (сейчас алиас `qwen3.8-flash`) — зависит от наличия снапшота у провайдера. До тех пор версию фиксируем лишь в `ParameterSource` и следим за дрейфом по градуснику (план 7).

## Не входит

- Измерение нестабильности прогоном одного текста N раз — отдельный дев-инструмент, не сюда.
- Эмбеддинги/примеры (план 8).

## Тесты

- Unit `TemperatureGroundingCheckerTest`: температура в тексте → нет варнинга; её нет → варнинг; число внутри большего числа (`1908` vs `90`) не считается совпадением; отрицательная (`-10`); несколько полей; null-поля игнорируются; температура из вложения (в собранном тексте есть) → нет варнинга.
- Unit `SystemSelectionProcessorTest`: добавить кейс «выдуманная температура → предупреждение в warnings».
- Unit `NetAngelsExtractorTest`: в теле запроса присутствует `seed`.

## Порядок

1. `TemperatureGroundingChecker` + юнит-тесты.
2. Проводка в `SystemSelectionProcessor` + кейс в тесте процессора.
3. `seed` в `NetAngelsExtractor` + проверка в тесте.
4. Гейты, прогон, при накоплении данных — смотреть на градуснике (план 7), уменьшились ли «разошлись» по температурам.
