# Спека: единый механизм опциональности/повтора в docx-движке шаблонов

**Дата дизайна:** 2026-09-25. **Статус:** дизайн одобрен (брейншторм), дальше — writing-plans.
**Затрагивает:** `app/src/Shared/Infrastructure/Service/DocxTemplateRenderer.php` + `DocxMacroProcessor.php`,
`app/src/Shared/Domain/Templating/*`. Потребители: Reports (акты, 11 .docx-шаблонов), Proposals (ТКП, xlsx — см. «Границы»).

## Проблема

Движок предлагает ПЯТЬ механизмов опциональности/повтора: `{{x}}` (обязательный), `{{x?}}` (опц. на месте),
`{{opt_x}}…{{/opt_x}}` (опц. абзац-блок), `{{?x}}…{{/?x}}` (инлайн-сегмент), `{{group}}…{{/group}}`+`{{group.sub}}`
(повтор). №3/4/5 на глаз почти одинаковы, ведут себя по-разному и **тихо корёжат документ при смешении**.
Подтверждённый баг: `{{?process}}` (сегмент) вокруг `{{process.description}}` (повтор) на одном имени `process` →
движок считает `process` повторяемой группой, зовёт PhpWord `deleteRow` на токене, лежащем в АБЗАЦЕ (не в `<w:tr>`)
→ PhpWord цепляет не ту границу `<w:tr>` → **документ обрывается**. Обходной `?`-на-каждом-внутреннем-токене чинит
пустой случай, но ломает непустой (повтор с данными не отрисовывается). Система непредсказуема.

## Цель

Одно интуитивное правило: **`?`-суффикс = «необязательно»; парные маркеры = регион; повтор = точечные подполя
внутри региона.** Автор шаблона переключает строгий↔необязательный добавлением/снятием `?` на паре маркеров —
единообразно для одиночных плейсхолдеров И групп/повторов. Никаких коллизий, никакого `?`-на-каждом-токене.

**Направление (контекст, влияет на инварианты):** позже шаблоны станут ЗАГРУЖАЕМЫМИ и выбираемыми пользователем;
отчёт — САМОДОСТАТОЧНЫМ (все данные в нём, шаблон — одно из представлений). Поэтому: контракт ключей стабилен и
документирован (`docs/plans/report-template-placeholders.md`); опциональность/строгость живёт В ШАБЛОНЕ (в его
маркерах), не в отчёте; валидация полноты — per-(шаблон, отчёт): движок парсит маркеры конкретного шаблона и сверяет
с данными отчёта. Сам аплоад — вне scope (YAGNI), но дизайн upload-ready. НЕ переносить опциональность в домен отчёта.

## Контракт синтаксиса (итог)

| Форма | Смысл | Нет данных |
|---|---|---|
| `{{x}}` | обязательный плейсхолдер | → `missing` (предупреждение, файл не собрать) |
| `{{x?}}` | необязательный плейсхолдер | → чистится на месте, литерал вокруг остаётся |
| `{{x}}…{{/x}}` | **обязательный** регион (повтор, если внутри `{{x.sub}}`) | → `missing` |
| `{{x?}}…{{/x?}}` | **необязательный** регион | → регион удаляется целиком, файл формируется |

- `?` — ВСЕГДА суффикс, ВСЕГДА значит «необязательно». `?` на открытии и закрытии региона согласованы
  (`{{x?}}…{{/x?}}`); рассинхрон (`{{x?}}…{{/x}}`) → человекочитаемая ошибка на parse/validate.
- Логическое имя = имя без `?`. Флаг `optional` = наличие `?`.
- Повтор = наличие точечных `{{x.sub}}` внутри региона (как сейчас).
- Удаляется что МЕЖДУ маркерами: чтобы при пустом регионе исчез и заголовок — автор заносит заголовок ВНУТРЬ маркеров.
- Инлайн-ниша «Датчик: {{sensor}}» = `{{sensor?}}Датчик: {{sensor}}{{/sensor?}}` (тот же опц-регион в одну строку).

## Механика движка

**`parse()` (+ `DocxMacroProcessor::normalizeMacros`):**
- Токен → `{logical, optional}`: `optional = str_ends_with(name, '?')`, `logical = rtrim('?')`. Работает и для маркеров
  региона (`{{x?}}` / `{{/x?}}`).
- Регион = парные open/close с совпадающим `?`. Повтор — регион с `{{logical.sub}}` внутри.
- **Опц. регион авто-детект инлайн vs блок:** если open и close в ОДНОМ `<w:p>` (абзаце/ячейке) → инлайн (вырез регэкспом,
  как прежний сегмент); если в разных абзацах → блок (PhpWord `deleteBlock`/`cloneBlock`). Это снимает нужду в двух
  синтаксисах (`{{opt_x}}` блок vs `{{?x}}` инлайн) — один `{{x?}}…{{/x?}}`, поведение по расположению маркеров.
- **Удаляется парсинг** префикса `{{?x}}`/`{{/?x}}` и `{{opt_x}}`/`{{/opt_x}}`.

**`validate()` → `ValidationResult` (`missing`/`skipped`/`unresolvedImages`/`unused`):**
- строгий (без `?`) и данных нет → `missing`. Единообразно: одиночный `{{x}}` И регион `{{x}}…{{/x}}` (пустой повтор =
  нет строк = нет данных). **Изменение против текущего**: сейчас повторы НИКОГДА не попадают в `missing` — теперь
  строгий пустой повтор попадает (даёт «строгий» из требования).
- опц. (`?`) и данных нет → `skipped`.
- строку повтора внутри валидируем как раньше по подполям (пустое подполе → чистится, строка остаётся); построчную
  обязательность полей держит доменный `ReportContentValidator`, движок отвечает лишь за наличие/отсутствие региона.

**`render()`:**
- одиночные — как сейчас (fill/clear).
- опц. регион: с данными → повтор клонирует (блок/строка/инлайн-keep); пусто → удаляется целиком (deleteBlock/
  deleteRow/инлайн-вырез).
- строгий пустой регион в render недостижим — `render()` сначала зовёт `validate()` и кидает `AppException` на непустом
  `missing`.

**Повтор СТРОКОЙ ТАБЛИЦЫ** (голые `{{g.sub}}` в `<w:tr>` без обёрточных маркеров): маркер `?` вешать некуда →
**опционален по природе** (пусто → строка-шаблон удаляется). Хочешь строгую таблицу — обернуть область в `{{g}}…{{/g}}`.
Поведение сохраняется как сейчас.

**Предсказуемость (корень бага закрыт):** префикса `{{?x}}` нет → коллизия «сегмент × повтор» на одном имени
невозможна. Внутренние `{{g.sub}}` никогда не требуют `?`. Повтор в абзацах = только блок (`cloneBlock`, безопасен),
`deleteRow` на абзацном токене больше не вызывается.

## Что удаляется + миграция шаблонов

Удалить из движка код префикс-сегмента `{{?x}}…{{/?x}}` и блока `{{opt_x}}…{{/opt_x}}` (последний НЕ используется нигде —
подтверждено обзором 11 шаблонов). Инлайн-сегмент используется только в `trial_application_1layer.docx`.

Миграция .docx (только там, где есть старые формы; `{{x?}}`-одиночные и `{{group}}`-повторы НЕ трогаем):
- `trial_application_1layer.docx`: `{{?process}}`→`{{process?}}` (или `{{process}}` если строгий), `{{/?process}}`→
  `{{/process?}}`; внутри `{{?process.description}}`→`{{process.description}}`, `{{?process.action}}`→`{{process.action}}`;
  `{{?sensor}}…{{/?sensor}}`→`{{sensor?}}…{{/sensor?}}`; `{{?surface_prep_blasting_media}}…`→`{{surface_prep_blasting_media?}}…{{/…?}}`.
- Остальные 10 шаблонов: старых форм №3/4 нет — правки не нужны; при желании переключить повтор в опциональный — добавить `?` на маркеры.
- **Инструмент миграции — скрипт python-zipfile** (замена в `word/document.xml`, текст не фрагментирован для этих
  маркеров после normalizeMacros; правило .docx-редактирования из [[project_field_reports_feature]]).
- Обновить контракт `docs/plans/report-template-placeholders.md`: описать 4 формы + `?`-правило + «заголовок внутрь».

## Тестирование (TDD)

Юнит движка (`DocxTemplateRenderer*Test`): по каждой форме — (a) строгий одиночный пусто → `missing`; (b) опц. одиночный
пусто → чисто на месте, литерал цел; (c) строгий регион пусто → `missing`; (d) опц. регион-блок пусто → удалён целиком,
контент ПОСЛЕ цел (регресс на баг обрыва); (e) опц. регион с данными → повтор по строкам; (f) инлайн опц. регион
(маркеры в одном абзаце) пусто → вырезан со словом, есть данные → заполнен; (g) рассинхрон `?` → человекочитаемая ошибка;
(h) повтор строкой таблицы пусто → строка удалена, шапка цела. Регресс: существующие повтор-тесты (commission/process/
recommendations/conclusion) зелёные. Reports functional: генерация полного отчёта → docx; отчёт без опц-блока → файл есть;
отчёт без строгого блока → предупреждение, файла нет.

## Откат/риск

- Изменение парсера/валидатора/рендерера общего движка — покрываем юнит-регрессом существующих сценариев.
- Реальные шаблоны в проде — мигрируем скриптом + проверяем `variables()`/рендер-смоук на каждом.
- «Строгий пустой повтор → missing» меняет поведение: раньше пустой повтор молча выпадал. После — если автор пометил
  строго и данных нет, файл не соберётся (это и есть требование). Опц-повторы (`?`) сохраняют прежнее «тихо выпал».
