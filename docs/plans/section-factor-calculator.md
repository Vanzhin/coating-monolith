# Калькулятор приведённой толщины металла (ПТМ)

Ветка: `feat/tools-section-factor` (от main). Один деплой (без миграции — сортамент датасетом в коде).

## Задача

Публичный офлайн-калькулятор **приведённой толщины металла** (`/tools/section-factor`) паттерном mix/film/consumption/dew-point: серверный доменный сервис — источник истины, расчёт в браузере ради офлайна, страница в precache, ядро — переиспользуемый partial (встраивается и в модалку).

`ПТМ = площадь поперечного сечения / обогреваемый периметр` (НПБ 236-97 / ГОСТ Р 53295), контурный метод (развёрнутый контур сечения — верно для тонкослойной/контурной огнезащиты).

Профили v1 (все 7): **двутавр, швеллер, уголок, труба, круг, профиль (квадрат/прямоугольник), лист**. Ввод — **по размерам + выбор из сортамента ГОСТ**. Схема обогрева — **пресеты (4-стор. / 3-стор.) + галочки по граням**.

Выводы: ПТМ (мм), обогреваемый периметр (мм), площадь поверхности / 1 м (м²), площадь поверхности / 1 т (м²), масса / 1 м (кг).

## Ключевые факты

- **Референсы:** собственный репозиторий `github.com/Vanzhin/Ptm-Calculator` (PHP CLI, источник формул) и `offire.ru/calculator` (UX, пропорции схем). offire дополнительно считает расход состава «Прометей» — **это не наш объём** (вендорское).
- **Аудит формул репо (проведён):** методика верная (ПТМ = A/P, контурный периметр; вывел вручную для трубы и двутавра — сошлось: двутавр 4 стороны = `4b + 2h − 2s`; швеллер — тригонометрия уклона полок `qj/wp` = град↔рад, при `u=0` корректно вырождается). Переводы единиц (площадь/1м, /1т, масса, плотность 7.85) верны.
- **Фиксы из аудита (в порт вносим, не копируем как есть):**
  1. **Лист:** убрать хардкод-таблицу `getCoefficient` (она буквально = `толщина×7.85`, падает на толщине не из списка) → считать `δ×7.85` напрямую (любая толщина). ПТМ листа = `δ / число обогреваемых граней` (2 грани → δ/2, 1 → δ), привязано к схеме обогрева.
  2. **Двутавр по размерам:** в репо вход `«ширина стенки»` = чистая высота стенки (h−2t) — неоднозначно, ввод полной высоты даёт тихо неверный ответ. У нас принимаем **полную высоту H**, `hw = H − 2t` считаем сами. На SVG-схеме подписи размеров снимают неоднозначность.
  3. **По размерам vs сортамент:** «по размерам» — без учёта закруглений (пометить в UI), сортамент — с fillet-коррекциями (R/r/u), точнее. Для мелких профилей разница заметна (20Б1: без R ≈ 2612 мм² против ГОСТ ≈ 2849, ~8%).
  4. **Круг** в репо отсутствует (404) — добавляем: сплошной пруток `ПТМ = D/4` (площадь `πD²/4`, периметр `πD`).
  5. Валидации сохраняем: «не обогревается ни одной грани», «толщина > габарита».
- **Сортамент:** ~250+ типоразмеров, ~110 КБ сырых (~20-30 КБ gzip) — лёгкий. Данные портируем из `standards_*.php` репо (двутавр/швеллер/уголок/профиль + DIN).
- **Доступ:** `/tools/*` публичен по умолчанию (в `security.yaml` не значится). `^/api` — под auth. Публичный JSON-эндпоинт сортамента кладём под `/api/tools` (конвенция «JSON под /api») + добавляем строку `^/api/tools → PUBLIC_ACCESS` **перед** `^/api` в `access_control` (по образцу `^/api/auth/token`).
- **Паттерн /tools:** ядро калькулятора — `<div data-controller="…">` в partial; страница = крошки+h1+intro+`{% include %}`+`<details>`; расчёт дублируется в Stimulus ради офлайна (докблок домена это разрешает, как `DewPointCalculator`/`FilmThicknessCalculator`); только существующие `bi-*`/классы карточек, новых цветов не сочинять.

## Развилки (согласовано с пользователем)

- Объём v1 — **только ПТМ** (геометрия). Подбор огнезащитных покрытий из каталога — **будущий отдельный деплой** (см. «Будущее»). Домен проектируем под это.
- Ввод — **по размерам + сортамент сразу**. Все 7 типов. Схема обогрева — пресеты + галочки по граням.
- **Сортамент — бэкенд-датасет в коде** (JSON, версионируется git), эндпоинт его отдаёт; фронт читает и кэширует у себя (Cache API/IndexedDB) для офлайна, обновляет по версии/ETag. **Без БД-таблицы и миграции.**
- **Сервис считает ПТМ из площади и обогреваемого периметра** (узкое ядро); геометрия профиля (размеры+схема → площадь, периметр) — отдельный доменный слой, поверх него ядро.
- **SVG-схемы профилей рисуем сами** (схематичные, не в масштабе, под нашу дизайн-систему); offire — только визуальный референс пропорций. Инлайн-SVG в Twig, подсветка обогреваемых граней — CSS-классом, Stimulus только тогглит.

## Файлы и задачи

### Задача 1. Домен: ядро ПТМ + геометрия профилей + схема обогрева

Дом — рядом с `Shared/Domain/Service/DewPointCalculator` (прецедент чистой физики в Shared).

**Create** `app/src/Shared/Domain/Service/SectionFactorCalculator.php` — ядро, считает **из площади и периметра**:
- `reducedThickness(PositiveNumber $area, PositiveNumber $perimeter): float` = `area/perimeter` (ПТМ, мм)
- `surfaceAreaPerMeter(PositiveNumber $perimeter): float` = `perimeter/1000` (м²)
- `massPerMeter(PositiveNumber $area): float` = `area/1000 * 7.85` (кг); `const STEEL_DENSITY = 7.85`
- `surfaceAreaPerTon(area, surfacePerMeter): float` = `1000/massPerMeter * surfacePerMeter` (м²)
- вход VO `PositiveNumber`, кидает `AppException`.

**Create** `app/src/Shared/Domain/Service/SectionFactor/ProfileType.php` — enum: `I_BEAM, CHANNEL, ANGLE, PIPE, ROUND_BAR, RECT_HOLLOW, SHEET`.

**Create** `app/src/Shared/Domain/Service/SectionFactor/HeatingScheme.php` — `final readonly` VO: грани `top/bottom/left/right` (bool); фабрики `allSides()`, `threeSided(Face $excluded)`; для трубы/круга — периметр по кольцу (грани не применимы, отдельный флаг/пресет). Валидация «≥1 обогреваемая грань» → `AppException`.

**Create** `app/src/Shared/Domain/Service/SectionFactor/ProfileSection.php` — интерфейс: `crossSectionArea(): float`, `heatedPerimeter(HeatingScheme $scheme): float`.

**Create** per-type `final readonly` реализации (портируем формулы репо + фиксы):
- `IBeamSection.php` — размеры H, b, s, t (+опц. R/r/u из сортамента); площадь `(H−2t)·s + 2·b·t (+fillet)`; периметр по граням.
- `ChannelSection.php` — H, b, s, t (+R/r/u); тригонометрия уклона полок.
- `AngleSection.php` — b1, b2, t (+R/r); площадь `(b1+b2−t)·t (+fillet)`.
- `PipeSection.php` — D, t; площадь `π/4·(D²−(D−2t)²)`, периметр `π·D`.
- `RoundBarSection.php` — D; площадь `πD²/4`, периметр `πD` (ПТМ = D/4). НОВОЕ.
- `RectHollowSection.php` — H, W, t (+R); наружный периметр.
- `SheetSection.php` — δ, число граней (1/2); ПТМ = `δ/грани`; масса/площадь через `δ×7.85`. Фикс листа.

Каждая секция чистая, кидает `AppException` на невалидных размерах.

### Задача 2. Сортамент: датасет + провайдер + эндпоинт

**Create** `app/src/Shared/Infrastructure/SectionFactor/sortament.json` — датасет, версионированный. **Дерево-каскад** (у offire выбор — водопад зависимых уровней, не плоский список): у каждого стандарта — упорядоченный список уровней и дерево, лист дерева = размеры:
```
{ "version": "<строка>", "types": { "i_beam": { "standards": {
    "gost-r-57837-2017": {
      "label": "ГОСТ Р 57837-2017",
      "levels": ["Тип", "Номер", "Вариант"],
      "tree": { "Б": { "20": { "1": {"h":200,"b":100,"s":5.5,"t":8,"R":11,"r":4,"u":0.09}, "2": {…} } },
                "Ш": {…}, "К": {…}, "Д": {…} } }, … } }, … } } }
```
- Двутавр: `["Тип","Номер","Вариант"]` (Б/Ш/К/Д…). Швеллер: `["Серия","Номер"]` (П/У/Л/Э). Уголок: `["Вид","Размер"]` (равно/неравнополочный). Профиль: `["Размер"]`. Глубина каскада = длина `levels`, разная у стандартов.
- Труба/круг/лист — без сортамента (только по размерам).
- Портируем из `standards_*.php` репо (там плоско `стандарт→типоразмер`) — при портировании раскладываем плоские обозначения в дерево по уровням (парс `20Б1` → Б/20/1); DIN — свои серии.

**Create** `app/src/Shared/Infrastructure/SectionFactor/SortamentProvider.php` — читает JSON (кэш в памяти), отдаёт массив/DTO + `version()`.

**Create** `app/src/Shared/Infrastructure/Controller/Tools/SortamentAction.php` — `#[Route('/api/tools/section-factor/sortament', name: 'app_api_tools_section_factor_sortament', methods: ['GET'])]`, тонкий: `JsonResponse::fromJsonString` из провайдера. Публичный.

> **Расхождение со спекой (реализовано так):** ETag/304 убран — глобальный `ResponseListener` (priority 200) оборачивает любой `application/json` в конверт `{result,status,data}`, создавая новый `JsonResponse` (мой ETag затирался). Офлайн/скорость держат клиентский localStorage-кэш + предкэш SW. Фронт читает `body.data`.

**Modify** `app/config/packages/security.yaml` — добавить `- { path: ^/api/tools, roles: PUBLIC_ACCESS }` **перед** строкой `^/api`.

### Задача 3. Фронт: partial-ядро + SVG-схемы + Stimulus

> **Раскладка (реализовано):** мобайл — одна колонка; десктоп (≥720px) — шире (`.sf-wide` 880px) и 2 колонки (слева схема+результаты, справа ввод), без вертикального скролла. Плюс **клик по стороне прямо на SVG-схеме** включает/выключает обогрев (зоны `.sf-hit`, метод `faceClick`), синхронно с галочками/пресетами. Красный (`--danger-strong`) — только в рисунке конструкции; кнопки-грани в активном состоянии выделяются серым.

**Create** `app/src/Shared/Infrastructure/Templates/tools/_section_factor_calculator.html.twig` — ядро `<div data-controller="section-factor-calculator">`:
- табы типа профиля (7);
- переключатель «из сортамента / по размерам»; при «сортамент» — **каскад зависимых select-ов по уровням дерева** (Стандарт → уровни из `levels` → лист), каждый следующий фильтруется предыдущим, на листе автоподстановка размеров; глубина адаптивна под стандарт; при «по размерам» — поля размеров с пометкой «без учёта закруглений»;
- схема обогрева: пресеты (4-стор./3-стор.) + галочки по граням (для трубы/круга скрыты — по кольцу; для листа — 1/2 грани);

- вывод: ПТМ, периметр, площадь/1м, площадь/1т, масса/1м — с `copy-value`.

**Create** `app/assets/controllers/section_factor_calculator_controller.js` — Stimulus, чистый клиент:

- загрузка сортамента: `fetch` эндпоинта при первом выборе «сортамент» → Cache API/IndexedDB (ключ по version); офлайн — из кэша; нет кэша → работает ручной ввод;
- подсветка граней: тоггл CSS-класса на элементах SVG по состоянию схемы;
- парс decimal / `inputmode` — как в mix/film.

**Create** CSS в `app/assets/styles/` (`components/*.css`, вероятно рядом с `components/tools.css`) — подсветка «горячей» грани строго существующими токенами: **обогреваемая грань = `--danger-strong` (+`--danger-subtle`), акцент = `--bs-primary`, сталь-заливка SVG = `--bs-secondary-bg`/edge `--bs-secondary-color`, утопленные зоны = `--bs-tertiary-bg`/`--sunken`**. Никаких новых цветов. SVG — `currentColor`/токены, тема-aware. Подключить через `@import` в `app.css`.
