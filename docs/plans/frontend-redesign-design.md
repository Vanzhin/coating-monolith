# Редизайн фронта: современный PWA app-shell — дизайн-спецификация

Статус: дизайн согласован через визуальный компаньон (2026-08-28). Это источник правды по облику. Реализация — отдельными планами по деплоям (см. раздел «Реализация — разбивка на деплои»).

Макеты (референсы): `.superpowers/brainstorm/*/content/*.html` — home-cabinet, list-final, quickview-sheet/quickview-chem, substance-search, nav-options, form-coating, compare-v2, system-editor, landing-auth, media-variants.

## 1. Цель и рамки

Сквозной редизайн фронта: современный, нейтральный вид (в духе GitHub, но новее), мобильная версия — как приложение (полноценный PWA). Охват — весь фронт: cabinet (покрытия, системы, документы, сравнение, ЛК), admin-CRUD, публичные (лендинг, вход/регистрация). ~74 twig-шаблона.

## 2. Ключевые решения (согласованы)

- **Мобайл = полноценный PWA**: манифест, service worker, установка на домашний экран, app-shell, native-переходы. Отдельного нативного приложения нет — «приложение» это установленный сайт.
- **Эстетика** — собственная нейтральная дизайн-система под 1helper (не iOS/Material), нейтральная как GitHub, но современнее.
- **Тех-основа** — слой поверх **Bootstrap 5.3** (не выкидываем). Сверху: дизайн-токены (CSS-vars, переопределяют тему Bootstrap) + app-shell + PWA + **View Transitions API** (MPA, без Turbo).
- **Тёмная/светлая** — через существующий `data-bs-theme` на `<html>` (FOUC-safe init уже есть).

## 3. Дизайн-токены

Определяются как CSS-переменные, переопределяющие тему Bootstrap. Две темы.

Светлая: `--bg #f6f7f9`, `--surface #fff`, `--sunken #f0f2f5`, `--border #e4e7ec`, `--border-strong #d4d8de`, `--text #14181f`, `--muted #616b7a`, `--faint #8b94a3`, `--accent #2f6feb` (fg #fff), `--accent-subtle #eaf1ff`. Статусы: ok #1a7f4b (subtle #e6f4ec), warn/diff #e0a83a (bg #fff6e6, txt #8a6d1a).

Тёмная: `--bg #0d1117`, `--surface #161b22`, `--sunken #1c222b`, `--border #2a3038`, `--border-strong #3a424d`, `--text #e6edf3`, `--muted #9aa5b1`, `--faint #6e7781`, `--accent #4d8bf5` (fg #0d1117), `--accent-subtle #17233b`. ok #3fb950, diff bg #2a2413.

Геометрия: радиусы 8 / 11–12 / 14–16 (контролы / карточки / крупные блоки). Тени — мягкие двухслойные; шрифт — системный стек (уже используется); motion — `cubic-bezier(.22,.61,.36,1)`, длительности 120–180 мс, уважать `prefers-reduced-motion`.

Реализация: слой токенов в `app/assets/styles/` (напр. `tokens.css` + маппинг на `--bs-*`), импорт в `app.css` **после** bootstrap. Большой inline-`<style>` из `base.html.twig` вынести в ассеты (заодно закрывает нарушение правила «в Twig только разметка»); inline-`<script>` (theme init оставить в head как critical-path, остальное — в Stimulus).

## 4. App-shell и навигация

**Нижняя таб-панель (мобайл), Вариант 2:** `Покрытия · Системы · Документы · Химстойкость · Ещё`. Иконки: сетка / стопка-слоёв / файл / колба / три-точки. Активный таб — акцент. `backdrop-filter` blur, safe-area padding снизу, home-indicator.
- «Главная» (дашборд кабинета) — по тапу на логотип в app-bar, не таб.
- «Ещё» — offcanvas/шит: аккаунт (ЛК), тема, выход, все админ-справочники (Производители, Химстойкость, Подготовка поверхности, Организации).

**Верхний app-bar (мобайл):** липкий, blur. Слева — логотип-бренд (тап = Главная), по центру/слева — крупный заголовок экрана (large title) либо контекстный заголовок; справа — иконка поиска и/или аватар. На под-экранах — стрелка «назад» слева.

**Десктоп:** боковая навигация (те же пункты + группа «Администрирование»), верхняя строка с заголовком/действиями, контент в читаемой ширине. Старый гамбургер-offcanvas как основной убираем.

**Native-переходы:** cross-document View Transitions API (progressive; где нет поддержки — обычный переход).

## 5. Единая entity-карточка

Одна форма карточки для покрытий/систем/документов. Состав: медиа-слот (46×46) + тело (заголовок + описание 2 строки clamp + мета-строка + опц. бейджи + теги-скролл) + действия (kebab «⋯» для админ-операций edit/delete/duplicate; чекбокс сравнения в углу — где применимо).

Медиа-слот адаптивен:
- **Покрытие** — плитка **C**: крупный монограм типа связующего (EP / PU / ЦС) + тонкая цветная полоса снизу (несколько доступных цветов). Тип связующего в тексте карточки НЕ дублируем; в мете — «N цветов». Важно: у покрытия МНОГО доступных цветов (`possibleColors`); один конкретный цвет бывает только у слоя системы.
- **Система** — иконка стопки слоёв; в мете — мини-свотчи слоёв (по одному цвету на слой) + счётчик документов.
- **Документ** — иконка файла со статусом; бейдж «действует до …» / «просрочен», организация.

Hover/tap: лёгкий подъём + тень. Выбранная для сравнения — рамка-акцент.

## 6. Экраны

### 6.1 Главная кабинета
Large-title app-bar + email/роль, строка поиска, секция «Разделы» (навигационные карточки Покрытия/Системы/Документы/Сравнение со счётчиками), «Примеры поиска» (пресет-фильтры строками с иконкой и стрелкой). Десктоп — боковая навигация + те же блоки.

### 6.2 Список (покрытия; тот же паттерн для систем/документов)
Крупный поиск → чипы-фасеты горизонтальным скроллом (активные залиты акцентом с «×»; «Все фильтры» — пунктирный чип со счётчиком, открывает шит фасетов) → entity-карточки → бесконечная прокрутка (fallback — пагинация). Создание: FAB «+» (мобайл) / кнопка в шапке (десктоп). Трей сравнения: плавающий над таб-панелью, **removable-чипы с названиями** покрытий (не цветные свотчи — промышленные палитры однотипны), «N из 4 · можно ещё M», кнопка «Сравнить».

### 6.3 Быстрый просмотр (bottom-sheet)
Тап по карточке → шит снизу (grabber, шапка с монограмом + производитель, кнопка ×). Тело: теги/описание; «Входит в системы» (чипы); **характеристики key-value списком** (не таблица): тип ЛКМ, сухой остаток, плотность, ТСП (мин–макс + цель), диапазон нанесения, сухое тепло, погружение, блеск, упаковка, разбавитель; «Возможные цвета» — свотчи + «Колеруемое» + «+N»; «Время высыхания» — матрица (гор. скролл, курсив=расчёт, ∞=без ограничения, «—»=нет данных). Химстойкость покрытия — только лёгкая сводка; полный разбор ушёл в экран «Поиск по веществу» (6.4); длинные списки — сворачиваемая секция (disc), при отсутствии данных секции нет. Липкие действия внизу: сравнение + «Редактировать» (админ). Десктоп — центрированная модалка.

### 6.4 Химстойкость — поиск по веществу (`/coatings/by-substance`, таб «Химстойкость»)
Ввод вещества с автокомплитом (из справочника, можно несколько) → результаты = entity-карточки покрытий + вердикт-пилюля (Стойкое / Ограниченно). Сегмент «Только стойкие / + ограниченно», счётчик, частые среды чипами при пустом вводе. Выносит тяжёлую химстойкость из карточки покрытия.

### 6.5 Форма (покрытие; тот же паттерн для систем/справочников)
Секции-карточки; под app-bar — **чипы-якоря секций** (быстрый переход по длинной форме). Поля: label сверху, контрол 44px (селекты с шевроном, теги-чипы, свотчи цветов с «+», тумблеры). Липкая панель «Отмена / Сохранить» снизу + дубль «Сохранить» в app-bar. Ввод длительности времени высыхания → **bottom-sheet** (сегмент «Значение / Без ограничения / Неизвестно» + степперы Дни/Часы/Минуты). Десктоп — **боковой липкий TOC** секций + поля в 2 колонки + панель сохранения снизу. Серверная валидация — источник истины (AppException → alert в форме); клиентская — только UX.

### 6.6 Сравнение (`/coatings/compare`)
Таблица «поле × покрытия»: первый столбец (поле) **липкий слева**, покрытия скроллятся вправо; шапка столбца = мини-монограм + короткое имя + **крестик «убрать из сравнения»**; пустой столбец «+ Добавить» (до 4). Различающиеся строки подсвечены (мягкий diff-цвет в токенах, полоса слева, точка). Тумблер «Только различия». Блок «Время высыхания» — матрицы по стадиям, различающиеся **столбцы** подсвечены. Десктоп — панель «Видимые поля» (чекбоксы) + таблица.

### 6.7 Редактор слоёв системы
Сверху — **визуальный разрез**: слои полосами (цвет = выбранный цвет слоя, высота ~ ТСП), снизу штрихованная сталь-основание, суммарная ТСП. Плашка **соответствия ISO 12944** (считается из слоёв, не вводится). Карточки слоёв (сверху вниз): ручка перетаскивания (reorder), свотч цвета (тап → шит выбора одного цвета из палитры покрытия, поиск по RAL), название + бейдж Zn(R) для цинкнаполненных, мета «производитель · тип · допустимо min–max мкм», **ТСП-степмер**, чип цвета, удаление. Кнопка «+ Добавить слой» (шит: поиск покрытия → ТСП → цвет). Локальный DOM до submit; на сервер — `layers[i][coatingId|dft|colorId]` → ReplaceLayers. Замороженная документом система — редактирование состава заблокировано (инвариант домена).

### 6.8 Лендинг + вход
Лендинг (незалогинен): брендовый знак, «1helper», подзаголовок, три фичи (Каталог ЛКМ, Подбор по среде, Сравнение), CTA «Войти / Регистрация», плашка «Установить как приложение» (показывается по `beforeinstallprompt`, скрыта если установлено/недоступно), мягкое свечение. Вход — passwordless magic-link: email → «Отправить ссылку» → «Проверьте почту»; подтверждение (`process_login_link`) → «Войти». Регистрация — email. Десктоп — сплит: герой + карточка входа.

### 6.9 Документы и админ-CRUD
Документы — та же entity-карточка (иконка файла + статус), список/фильтры/форма по общим паттернам (6.2/6.5). Админ-справочники (Производители, Химстойкость, Организации, Подготовка поверхности) — те же список + форма, доступ под ROLE_ADMIN, вход через «Ещё» / боковую навигацию.

### 6.10 Состояния: ошибки валидации и flash
Серверная валидация — источник истины (клиентская — только UX-подсказка; без JS форма обязана работать).
- **Ошибка инварианта (AppException, HTTP 422)** — алерт вверху формы: danger-подложка/рамка, иконка, заголовок «Не удалось сохранить» + человекочитаемое сообщение из исключения. Введённые значения сохраняются.
- **Ошибки полей** — контрол с danger-рамкой + `box-shadow` danger-subtle, под полем — подпись с иконкой; групповые ошибки (напр. мин/макс) — под группой полей.
- **Flash-тосты** — подтверждения/ошибки действий: карточка с иконкой-тайлом (ok/danger/warning/info), заголовок + опц. подзаголовок, крестик. Позиция: мобайл — сверху под app-bar, десктоп — сверху справа. Auto-dismiss: success ~5с (полоса прогресса), warning/danger/info ~10с; вручную — крестиком. Реализация — переиспользуем существующий механизм flash (`app.flashes`) + Stimulus/Bootstrap Alert, стилизуем под токены; режим исполнения роли (impersonation) — info-тост со ссылкой выхода.
- **Inline-состояния** (empty-state списка, contextual info) — не тосты, а карточки в потоке контента.

## 7. PWA

- **Манифест** (сейчас пустой, пути к иконкам сбиты): заполнить name/short_name, `display: standalone`, theme/background по теме, исправить пути иконок (`/icons/...`), добавить maskable-иконку при необходимости.
- **Service worker**: кэш app-shell (оболочка, статика), офлайн-fallback страница; стратегия — network-first для данных, cache-first для статики. Регистрация из `app.js`.
- **Установка**: перехват `beforeinstallprompt`, кнопка «Установить как приложение» (лендинг + пункт в «Ещё»).
- **Native-переходы**: View Transitions API (opt-in через meta/CSS), деградирует безопасно.

## 8. Компоненты и где живёт код

- Токены/темы: `app/assets/styles/tokens.css` (+ маппинг на `--bs-*`), импорт в `app.css` после bootstrap.
- App-shell (таб-панель, app-bar, offcanvas «Ещё»): партиалы в `base.html.twig` / выделенные `Templates/_shell/*`, CSS в `assets/styles/components/`, поведение — Stimulus-контроллеры в `assets/controllers/` (напр. `bottom_nav`, `install_prompt`, `view_transitions`).
- Единая карточка: партиал-компонент (Twig include/embed или Live/Twig-component) — один источник разметки, параметризуется типом сущности (медиа-слот).
- Bottom-sheet, степперы длительности, шит выбора цвета, шит фасетов: Stimulus + `<template>` (без дублирования HTML между Twig и JS).
- Существующие контроллеры (compare-tray, chip-facets, infinite-list, range-filter, layer-color, coating-preview-loader и т.д.) — переиспользуем/адаптируем под новую разметку, HTML не дублируем.
- Вынести inline-`<style>`/`<script>` из `base.html.twig` (кроме FOUC-critical theme-init в head).

## 9. Реализация — разбивка на деплои

Задача многодеплойная → отдельные планы (`docs/plans/frontend-redesign-N-*.md`), не один большой. Предлагаемая последовательность (каждый — самодостаточный, зелёный, деплоится независимо):

1. **Фундамент**: дизайн-токены + вынос inline-style/script из base + маппинг на Bootstrap-vars. Визуально аккуратный рефреш без смены каркаса. Без регрессий.
2. **App-shell + навигация**: нижняя таб-панель (Вариант 2), app-bar, offcanvas «Ещё», десктоп-боковая навигация, View Transitions. Home по логотипу.
3. **PWA-каркас**: манифест + service worker + install-prompt + иконки/splash.
4. **Единая entity-карточка + списки** (покрытия/системы/документы) + фасеты/трей сравнения на новой карточке.
5. **Быстрый просмотр (bottom-sheet)** + матрица высыхания + сводка стойкости.
6. **Экран «Поиск по веществу»** (таб «Вещество»).
7. **Формы** (покрытие/система/справочники): секции+якоря+липкое сохранение, bottom-sheet длительности, редактор слоёв (разрез + карточки + шит цвета), десктоп-TOC.
8. **Сравнение**: липкий столбец, подсветка различий, удаление столбца, «только различия».
9. **Лендинг + вход/регистрация**.
10. **Админ-CRUD доводка** + чистка легаси-разметки.

Порядок в п.4–10 можно тасовать; п.1–3 — базис, идут первыми.

## 10. Ограничения и проверка

- Работать без JS форма/списки обязаны (серверная валидация/пагинация — fallback). PWA/переходы/шиты — прогрессивное улучшение.
- Тач-таргеты ≥44px, safe-area insets, `prefers-reduced-motion`, контраст в обеих темах.
- После правок CSS/JS/Twig — `cd app && yarn dev`; прогон затронутых тестов; визуальная проверка ключевых экранов в обеих темах и на узком экране.
- Email-шаблоны (10 шт) — вне охвата.
