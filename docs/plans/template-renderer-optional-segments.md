# Движок документов: инлайновые опциональные сегменты `{{?name}}…{{/?name}}` (Word)

## Задача

Спрятать литеральный текст вокруг плейсхолдера, когда значения нет. Кейс: в шаблоне
`…{{instruments.serial}} датчик {{instruments.sensor}};…` при пустом датчике должно исчезнуть и
слово «датчик», и «;», а не остаться «датчик ;».

Существующая опциональность это не решает:
- `{{name?}}` — чистит только сам плейсхолдер, литерал вокруг остаётся.
- блок `{{opt}}…{{/opt}}` — presence-driven, all-or-none, **абзацного уровня** (PhpWord `deleteBlock`
  работает по маркерам-абзацам) и **только верхний уровень** (члены блоков исключают repeat-члены).

Нужен инлайновый условный сегмент, работающий и на верхнем уровне, и внутри повторяемых групп.

## Область (согласовано)

- Унифицированно: и верхний уровень, и повторяемые группы (строка таблицы / блок-список).
- Только **docx** (`DocxTemplateRenderer`). Xlsx — отдельная задача, не сейчас.
- Тело документа. Колонтитулы/сноски — не поддерживаем (как и блоки; задокументировать).

## Синтаксис

```
{{?name}}любой литерал {{placeholder}} и ещё литерал{{/?name}}
```

- `name` — имя поля, от наличия которого зависит сегмент:
  - верхний уровень → плоское поле; критерий `RenderData::has(name)`;
  - внутри повторяемой группы → **ключ подполя** строки (напр. `sensor` при группе `instruments`);
    критерий — непустое `rows[i][name]`.
- Наличие → остаётся внутренний текст (маркеры снимаются, `{{placeholder}}` заполняется как обычно).
- Отсутствие/пусто → весь регион между маркерами вырезается целиком (литерал + плейсхолдер).
- Маркеры симметричны и оба несут `?`: `{{?name}}` / `{{/?name}}`. Это отличает их от блоков
  (`{{name}}`/`{{/name}}`) и от опциональных `{{name?}}`.
- Внутри сегмента разрешён ровно один связанный плейсхолдер (обычно `{{name}}` вверху либо
  `{{group.name}}` в повторе), но допустим и «пустой» сегмент без плейсхолдера — условие берётся из `name`.

Ограничения (задокументировать в PHPDoc драйвера):
- Сегмент — инлайновый, целиком в одном абзаце/ячейке (маркеры не разносим по абзацам).
- Вложенность сегментов и «сегмент внутри блока `{{opt}}`» — не поддерживаются в этой итерации.

## Три поддерживаемых случая (важно — повтор уже опционален сам по себе)

`{{?name}}…{{/?name}}` — условный литерал/регион, завязанный на `name`. НЕ разворачивает повтор
(разворачивает блок-повтор `{{group}}…{{/group}}`, он уже есть). Критерий по `name`:
верхний уровень → `RenderData::has(name)` (для группы = есть строки), внутри повтора → непустое
`rows[i][sub]`.

**Случай 1 — литералы ВНУТРИ повторяемого блока: сегмент НЕ нужен.** Пустая группа сносится целиком с
литералами внутри существующим блок-повтором:
```
{{process}}
{{process.description}} — корректирующее действие: {{process.action}}
{{/process}}
```

**Случай 2 — литерал/заголовок СНАРУЖИ блока: для этого и сегмент.** Заголовок перед списком должен
исчезнуть вместе с пустым списком; блок-повтор его не трогает (он вне блока), `{{opt}}`-блок не умеет
(repeat-члены не входят в его membership). Сегмент по присутствию группы:
```
{{?process}}Выявленные несоответствия:
{{process}}
{{process.description}}
{{/process}}
{{/?process}}
```
Имя сегмента = имя группы здесь ЛЕГАЛЬНО (сегмент оборачивает блок целиком). Механика: top-level проход
по `has(process)` до repeat-цикла — есть → снять маркеры (блок останется, repeat-цикл его клонирует);
нет → вырезать весь регион вместе с блок-маркерами (repeat-цикл ничего не найдёт, ошибки нет).

**Случай 3 — опциональное ПОДПОЛЕ внутри строки (кейс датчика).**
```
{{instruments.name}}{{?sensor}}, датчик {{instruments.sensor}}{{/?sensor}}
```

**Единственный сломанный случай (нужна внятная ошибка):** обернуть `{{?process}}` вокруг ГОЛЫХ
repeat-членов `{{process.description}}` БЕЗ блока `{{process}}…{{/process}}`. При наличии данных
repeat-член останется вне строки таблицы/блока → `repeatRow` → PhpWord Exception. Существующий
try/catch в repeat-цикле уже отдаёт человекочитаемую ошибку — отдельный parse-guard НЕ вводим (он бы
ложно ронял легальный случай 2). Достаточно уточнить текст существующей ошибки, что region можно
обернуть блоком `{{process}}…{{/process}}` внутри сегмента.

## Спайк (выполнен, риск снят)

PhpWord 1.4 `indexClonedVariables`:
`preg_replace('/\{\{([^:]*?)(:.*?)?\}\}/', '{{\1#'.$i.'\2}}', $xmlBlock)` — индексирует ЛЮБОЙ `{{...}}`
в клонируемом фрагменте. `?sensor` / `/?sensor` (без `:`) → `{{?sensor#i}}` / `{{/?sensor#i}}`,
синхронно с `{{instruments.sensor#i}}`. Значит номер строки `#i` доступен прямо из маркера сегмента.
`cloneRow`/`cloneBlock(...indexVariables=true)` оба идут через `indexClonedVariables` → верно для обоих.

## Дизайн реализации

### 1. Разбор — `DocxTemplateRenderer::parse`

Сейчас `parse` идёт по `orderedMacros()` и различает: закрытие блока (`str_starts_with('/')`),
открытие блока (в `closeSet`), repeat-член (`group.sub`), иначе — значение (опционально по хвосту `?`).

Добавить распознавание маркеров сегмента ПЕРВЫМ (до блочных проверок), т.к. `/?name` начинается с `/`
и иначе будет ошибочно принят за закрытие блока:

- токен вида `?name` (начинается с `?`, дальше `[a-z0-9_]+`) → **segment-open**;
- токен вида `/?name` → **segment-close**.

Segment-маркеры:
- не значения, не блоки, не repeat-члены — в `values`/`blocks`/`repeats` не попадают;
- ведём стек сегментов (как стек блоков): значения ВНУТРИ сегмента получают `optional = true`
  (иначе `validate` посчитает внутренний `{{name}}` пропущенным обязательным). Repeat-члены внутри
  сегмента уже опциональны по природе — их это не касается.

Вернуть из `parse` дополнительно список имён сегментов (для строгой проверки в render — все ли
маркеры вырезаны). Достаточно множества `segmentNames` и признака сбалансированности.

### 2. Верхний уровень — новый проход ДО заливки значений (`render`)

Новый метод в `DocxMacroProcessor`, работающий по `tempDocumentMainPart`:

```
resolveTopLevelSegments(array $present): void
```
где `$present[name] = bool` (из `RenderData::has(name)`), для каждого top-level `name`:
- регэксп (флаги `su`, non-greedy): `\{\{\?NAME\}\}(.*?)\{\{/\?NAME\}\}`;
- `has` истина → заменить на группу 1 (снять маркеры, оставить внутренний текст/плейсхолдер);
- иначе → заменить на `''`.

Вызвать в `render` ПОСЛЕ `blockStates`/удаления блоков, но ДО цикла `fill(...)`: тогда сохранённый
`{{name}}` внутри выжившего сегмента дозаполнит обычный `fill`, а у вырезанного — плейсхолдера уже нет
(guard остатков не сработает).

Имена top-level сегментов брать из `parse` (те, что не оказались resolved как repeat-члены).
NAME в регэкспе — `preg_quote`.

### 3. Повторяемые группы — пост-проход после клонирования (`repeatRow` / `repeatBlock`)

Не трогаем `cloneRowAndSetValues` / `cloneBlock` — они заполнили `{{group.sub#i}}`, а маркеры
`{{?sub#i}}` / `{{/?sub#i}}` остались сырыми. После while-цикла клонирования группы вызвать:

```
resolveRowSegments(array $rows, list<string> $subs): void   // метод DocxMacroProcessor
```
для каждого `sub` из `$subs` и каждого клона `#i` (i = 1..count(rows)):
- регэксп `\{\{\?SUB#I\}\}(.*?)\{\{/\?SUB#I\}\}`;
- непустое `rows[i-1][sub]` → оставить группу 1 (маркеры снять);
- пусто → вырезать.

`SUB`, `I` — `preg_quote` / число. Разрешение per-group снимает неоднозначность, если один и тот же
`sub` (напр. `sensor`) встречается в разных группах: на момент вызова проиндексированы `#i` только у
уже клонированной группы; чужие маркеры ещё `{{?sensor}}` без `#i` и под `#I`-регэксп не попадают.

Пустой список строк (группа удалена целиком) — сегменты уходят вместе со строкой-шаблоном, отдельной
обработки не требуют.

### 4. Валидация — `DocxTemplateRenderer::validate`

- Внутренние значения сегментов уже помечены `optional` в `parse` → отсутствие даёт `skipped`, не
  `missing`. Отдельной ветки не нужно, кроме проверки, что маркеры сегментов не утекли в `unused`/
  `missing`.
- Опционально: диагностика несбалансированных сегментов (открыт без закрытия) → внятная `AppException`
  вместо «не заполнены плейсхолдеры» от guard'а остатков. Nice-to-have, не блокер.

### 5. Guard остатков (`render`, конец)

После обоих проходов ни `{{?...}}`, ни `{{/?...}}` остаться не должны. Существующий
`orderedMacros()`-guard это и поймает; убедиться, что регэкспы вырезают ОБА маркера.

## Файлы

- `app/src/Shared/Infrastructure/Service/DocxMacroProcessor.php` — методы
  `resolveTopLevelSegments`, `resolveRowSegments` (доступ к `$this->tempDocumentMainPart`).
- `app/src/Shared/Infrastructure/Service/DocxTemplateRenderer.php` — `parse` (распознавание сегментов
  + optional внутри), `render` (вызов top-level прохода), `repeatRow`/`repeatBlock` (вызов row-прохода),
  `validate` (маркеры не попадают в missing/unused).
- Шаблоны отчётов (`trial_application_*.docx`, `reference_area*.docx`) — обернуть «датчик …» в
  `{{?sensor}}…{{/?sensor}}`. Отдельным шагом после зелёного движка; правку docx делает
  пользователь/отдельная мелкая задача (бинарь).

## Тесты

Зеркалят `src/`, гонять в контейнере `manager_php-fpm` (хост PHP 8.5 не заводит phpword).

- `tests/Unit/Shared/Infrastructure/Service/DocxTemplateRendererTest.php` — добавить кейсы:
  1. top-level сегмент, значение есть → литерал+значение остаются.
  2. top-level сегмент, значения нет → регион (литерал+плейсхолдер) вырезан целиком.
  3. повтор: строка с непустым sub → «датчик X;»; строка с пустым sub → без «датчик» и «;».
  4. смешанные строки в одной таблице (часть с датчиком, часть без) — каждая режется по своему `#i`.
  5. два сегмента с одинаковым `sub` в разных группах — не путаются.
  6. пустой сегмент без плейсхолдера — условие только по `name`.
  7. случай 2: сегмент оборачивает заголовок + блок-повтор `{{process}}…{{/process}}`; пусто →
     исчезает и заголовок, и блок; есть строки → заголовок один раз + список повторён.
  8. guard: несбалансированный сегмент → внятная ошибка (если реализуем п.4-диагностику).
- Фикстуры docx собирать программно через PhpWord (как в существующих тестах движка) либо мелкие
  заготовки рядом с тестом.

## Порядок работ

1. Тест-кейсы top-level (1–2) — красные.
2. `parse`: распознавание сегментов + optional внутри; `resolveTopLevelSegments`; вызов в `render`.
   Зелёные 1–2.
3. Тест-кейсы повтора (3–6) — красные.
4. `resolveRowSegments`; вызовы в `repeatRow`/`repeatBlock`. Зелёные 3–6.
5. `validate`: маркеры не в missing/unused; (опц.) диагностика дисбаланса + тест 7.
6. `./run check` зелёный (style/phpstan L6/unit/functional).
7. Обновить PHPDoc `DocxTemplateRenderer` (описание сегментов + ограничения).
8. Отдельным шагом: правка docx-шаблонов отчётов (обернуть «датчик …»).

- Колонтитулы, вложенные сегменты, сегмент-в-блоке — не поддерживаем; задокументировать.
