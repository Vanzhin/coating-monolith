# Исправления автозаполнения и формы путевого листа

Статус: реализовано; профильные проверки пройдены.

## Контекст

Ревью подтвердило шесть дефектов: новые ручные поездки получают чужой для черновика UUID, пустой маршрут теряет предшественника, повторное заполнение меняет отправление ручной строки, месячный подбор превышает 30 секунд, ошибка заполнения сбрасывает конечный одометр, а старые периоды без поездок сохраняют время, невидимое в date-only форме.

## Изменения

1. Строить полный маршрут один раз и сохранять его предшественника, включая пустой `Route`. При отборе неизменяемых поездок доменный `Route` перелинковывает только ручные записи и отклоняет неявное изменение их отправления. Ручная строка внутри автоматической пары переводит всю пару в ручные.
2. В предпросмотре очищать UUID только новых ручных строк, не ослабляя проверку принадлежности сохранённых идентификаторов. Начальную точку формы получать из предшественника маршрута; для создания загружать её только после проверки права создать лист для автомобиля.
3. Заменить перебор вариантов каждой пары перебором количества пар по направлениям. Для вектора количеств использовать точную достижимость по интервалам, минимальное отклонение `|T-E|`, прежние приоритеты и разбиение нечётной пары на `floor/ceil`. Произвольные лимиты не вводить.
4. При сохранении через форму нормализовать период листа и периоды без поездок к полным календарным дням с сохранением часового пояса. Миграцию не добавлять. Ошибки конфликтов оставляют сохранение атомарным; точное время поездок и заправок не меняется.
5. После повторного показа формы с ошибкой не пересчитывать введённый конечный одометр при `connect()`. Пересчёт при пользовательских изменениях поездок сохранить.

## Тесты

- Создание и редактирование: ручные поездки → заполнение → повторное заполнение → сохранение; нулевой остаток и отредактированные автоматические пары.
- Предшественник: автомобиль уехал с исходной базы; автомобиль вернулся на базу, отличную от исходной точки. Форма показывает фактическое отправление.
- Сценарий `А → Б → В → А` при повторном заполнении и ошибка при невозможности сохранить ручное отправление.
- Подбор: исходные `1000 км / 22 дня / 7 направлений`, малые exhaustive-сравнения со старым алгоритмом, нечётные суммы, нулевой остаток, невозможные суммы и нехватка дней.
- Нормализация старых периодов, часовые пояса, конфликт с поездкой/заправкой; точность вложенных операций сохраняется.
- JS: значение `120` после ошибки не заменяется начальным `100`; обычный пересчёт работает.
