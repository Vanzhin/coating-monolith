# План: Inquiries — веб-форма подбора по тексту/файлам + экран результата

Деплой 4. Первый триггер движка ([план 3](inquiries-3-engine-and-storage.md)). Второй (почта) — [план 6](inquiries-6-mail.md), то же ядро.

## Идея

Страница в кабинете: инженер вставляет текст и/или грузит файлы → движок обрабатывает → экран результата показывает **ВСЁ двумя слоями**: что реально в файле и что из него извлечено, плюс найденные системы и ссылку на фильтр с подставленными параметрами. Параметры **редактируемые** — инженер докручивает; правка сохраняется как «исправлено инженером» (топливо для плана 5).

## Решения

- **Тонкие per-action контроллеры** (Inquiries/Infrastructure/Controller), как `Coatings/.../CoatingSystem/{Add,List}Action`. Авторизация — `InquiryAccessControl` в хендлере, не `#[IsGranted]`.
- **Форма**: textarea (текст) + мультизагрузка файлов (multipart). Файлы → Shared/File (stage) → разборщик (движок).
- **Экран результата — слои рядом** (идея «четыре слоя» из podbor-плана, для инженера):
  1. **Вход**: текст + список вложений (имя, тип, размер).
  2. **Что в файле**: извлечённый текст по каждому вложению + статус (EXTRACTED/**SCAN**/ERROR) — инженер видит, что скан/битое не разобрано.
  3. **Что извлечено**: распознанные параметры (**редактируемые**), `specifiedCoatings` («клиент задал: …»), отчёт маппинга (какие вещества нашлись/нет, что отброшено).
  4. **Результат подбора**: карточки/ссылки найденных систем + **ссылка на фильтр** с подставленными параметрами.
- **Ссылка на фильтр**: query из смапленных параметров (`substrates[]`, `environment`, `standard`, `category`, `durability`, `thermTemp`/`thermEnv`/`thermPeak`, `substanceIds[]`, `minApplicationTimeAt20` **в ЧАСАХ**) → `/cabinet/coating/coating-system/list`. Несёт id запроса — правка+«найти» сохраняется как коррекция инженера.
- **Правка параметров**: отредактировал → пере-подбор (переиспользуем страницу фильтра / отдельный re-search action), результат-коррекция пишется в `Inquiry`.
- **Стиль — копируем ближайший аналог** (список систем/карточка Coatings), без новых классов/цветов; поиск-и-выбор — общий `typeahead`.

## Файлы

- `Inquiries/Infrastructure/Controller/{SubmitInquiryAction, ShowInquiryAction, ListInquiriesAction}.php`
- `Templates/cabinet/inquiry/{form, result, list}.html.twig` (копия разметки ближайших cabinet-шаблонов)
- `app/assets/controllers/` — при необходимости Stimulus для загрузки/редактирования (без дублирования HTML между Twig и JS).
- Тесты контроллеров.

## Тесты

- Functional контроллера: submit текст (+ fake-файл) с `FakeExtractor` → экран результата содержит извлечённые параметры, статусы вложений, системы.
- Round-trip: отредактировал параметр → пере-подбор → коррекция сохранена в `Inquiry`.
- Контроллер-тест авторизации (кто вправе запускать).

## Развилки

- **Кто вправе запускать** (стоимость LLM) — наследуется из [плана 3](inquiries-3-engine-and-storage.md); кнопка под `{% if canEdit %}`, гейт в хендлере.
- Редактируемые параметры: пере-подбор через существующую страницу фильтра (ссылка) vs инлайн-пересчёт на месте. Предлагаю начать со ссылки на фильтр (готовое), инлайн — потом.
- Показ «что в файле» для длинного текста — свернуть/развернуть (не раздувать экран).
