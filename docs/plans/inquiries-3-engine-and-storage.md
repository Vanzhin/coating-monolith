# План: Inquiries — агрегат Inquiry (общий, типизированный) + движок обработки

Деплой 3 — фундамент контекста. Соседи: [1-экстрактор](inquiries-1-extractor-netangels.md), [2-подбор системы](inquiries-2-mapper-filter.md), [4-веб](inquiries-4-web.md), [5-без модели](inquiries-5-templates-and-cache.md), [6-почта](inquiries-6-mail.md).

## Идея

Inquiries — **универсальный журнал «запрос → ответ → кем проверено»**, типизированный. Домен `Inquiry` знает ТОЛЬКО свои данные — **ноль знаний о Coatings / ChemicalResistance / любом чужом домене**. Он хранилище: вход, распознанные параметры, ответ, пометки проверки. Вся обработка (извлечение + резолв веществ + подбор) — оркестрация в Application, которая пишет готовый выход в `Inquiry` как данные.

Типов запроса несколько: `подбор_системы` (первый), дальше `подбор_покрытия` и прочие — общий вход для любых «спросили — ответили». Новый тип = новый процессор + значение `type`, домен не трогаем.

## Модель (Domain — чистое хранилище, свои плоские типы)

Агрегат `Inquiry`:
- **type** — что за запрос (`SYSTEM_SELECTION` первый; расширяемо).
- **вход**: источник (email/web), сырой текст, вложения (ссылка на файл в Shared/File + имя/тип/размер + **хеш** + извлечённый текст + статус разбора EXTRACTED/SCAN/ERROR).
- **распознанные параметры**: **непрозрачные данные** (key-value, собственный VO / jsonb) — то, что извлёк процессор. Домен их НЕ трактует («steel_carbon» для него строка).
- **ответ**: снимок результата (для подбора системы — id найденных систем + подписи + количество). Тоже непрозрачно — храним как данные, для истории/показа.
- **проверка**: статус, кем проверено, флаг **«одобрено»**, **diff правок** инженера (модель-оригинал → утверждённое).
- **служебное / топливо кэша** (план 5): метаданные извлечения (стратегия `llm/cache/template`, модель, токены, время), **сигнатура** документа, **хеш** входа, **эмбеддинг** входа, **нормализованные ключевые сущности** (вещества/температуры/подложка) — складываем с первого дня.
- статус-машина: получено → распознано → подобрано → одобрено / ошибка-на-шаге-N (с текстом).

Инварианты — только свои, без чужих типов: нельзя «распознано» без параметров; нельзя «одобрено» без распознанных параметров; и т.п. Никаких `CoatingSystemsFilter`/`Substrate`/чужих DTO внутри домена.

## Движок / процессор (Application — единственное место, где пересекаем границы)

- **`ProcessInquiryHandler`** (по типу): для `подбора системы` оркеструет — разборщик файлов ([Shared](shared-file-text-extractor.md)) → extractor (порт, [план 1](inquiries-1-extractor-netangels.md)) → **подбор** ([план 2](inquiries-2-mapper-filter.md): резолв веществ + запрос систем у Coatings) → пишет распознанные параметры + ответ в `Inquiry`.
- Процессор знает **Application-контракты соседей** (их query → DTO), НЕ их домены. Домен `Inquiry` не знает и этого — получает уже готовые данные.
- Вход (text + files) → склейка текста (тело + тексты вложений со статусами) → extractor.
- Хранение вложений — через Shared/File (stage → promote).
- Доступ — `InquiryAccessControl` в Application (запуск стоит денег/LLM — см. развилку).

## Валидация инженером (механизм)

Проверяется **связка «вход → параметры»** (там ошибается модель; системы из параметров детерминированны):
- экран-процессор типа показывает вход ↔ распознанные параметры (**редактируемые**) ↔ выдачу;
- инженер правит поле → **пере-подбор** → свежая выдача;
- «Одобрить» → в `Inquiry` пишутся исправленные параметры + выдача = проверенный выход, флаг «одобрено» + кто + diff;
- одобренная связка питает семантический кэш (план 5) и показывает системные ошибки модели.

Домен при этом слеп: схему параметров знает процессор/представление типа; `Inquiry` хранит выход как данные + «одобрено» + diff.

## Тесты

- Functional `ProcessInquiryHandler` с `FakeExtractor` + фейковыми запросами соседей (без сети): текст+файл → `Inquiry` сохранён (вход, распознанные параметры, ответ, статус).
- Functional: вложение-скан → статус SCAN, запрос не падает, дошёл до extractor с текстом тела.
- Unit агрегата: инварианты статуса; «одобрено» требует параметров; diff правок.

## Развилки

- **Хранение распознанных параметров/ответа** — jsonb (непрозрачно, гибко) vs типизированный-но-слепой VO. Предлагаю jsonb-VO: домен видит key-value, не трактует.
- **Снимок ответа** — id систем + подписи + количество (не тексты систем — меняются).
- **Уровни одобрения**: «параметры распознаны верно» (ключевое для кэша) vs ещё и «ответ — хороший» (мягкое доменное суждение). Начать с первого; второй флаг — при нужде.
- **Кто вправе запускать** (стоимость LLM): ограничить (ROLE/спец-право) — уточнить.
- Синхронно (веб) vs в воркере (почта) — движок один, различается триггер.
