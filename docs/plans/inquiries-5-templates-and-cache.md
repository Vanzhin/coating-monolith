# План (эскиз, позже): Inquiries — разбор без модели (кэш + шаблоны)

Деплой 5. Делается ПОСЛЕ накопления данных в проде через [1-4]. Опирается на хранение из [плана 3](inquiries-3-engine-and-storage.md) (хеши, сигнатуры, одобренные правки). Движок и веб/почта НЕ меняются — всё за существующим портом `InquiryParametersExtractor`.

## Идея

Снизить долю LLM-вызовов: частотные/повторяющиеся запросы разбирать детерминированно. Порт становится **цепочкой стратегий** (первая сработавшая отвечает):

1. **CacheExtractor** — хеш входа (файла/склеенного текста) совпал с ранее обработанным и **одобренным** инженером → отдаём тот результат. Без модели.
2. **TemplateExtractor** — вход опознан как знакомая форма по **сигнатуре** (напр. ОНХП-опросник `…-П-ОЛ…`: `pdftotext -layout` даёт стабильную таблицу) → достаём поля правилами (продукт из «Наименование рабочей среды», срок из «Срок службы АКП», температуры из «Расчётная температура» и т.п.). Без модели.
3. **NetAngelsExtractor** (LLM) — фолбэк (план 1).

## Решения (предварительно)

- `ChainInquiryParametersExtractor implements InquiryParametersExtractor` — обёртка над списком стратегий; первая непустая/уверенная выигрывает; стратегия фиксируется в метаданных (`cache`/`template:<id>`/`llm:netangels`).
- Кэш — по хешу содержимого; переиспользуем ТОЛЬКО одобренные результаты (иначе тиражируем ошибки модели).
- Шаблоны — реестр правил, ключ = сигнатура документа; правила над `pdftotext -layout`-текстом (регэкспы/позиционный разбор). Новый шаблон = новый класс + регистрация, без правок движка.
- Метрика: доля запросов без модели, экономия токенов.

## Развилки (на момент реализации)

- Что считать «той же формой» (сигнатура: штамп/набор заголовков/Producer PDF).
- Порог уверенности шаблона, прежде чем не звать LLM.
- Инвалидция кэша при смене версии промпта/правил.
- Сканы (нет текста) — сюда не относятся, им нужен OCR/vision (отдельная ветка).
