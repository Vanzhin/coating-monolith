# Прямой переход к форме путевого листа

Статус: реализовано. Одна поставка, без миграций.

## Контекст

Сейчас список ведёт на отдельный просмотр `GET /cabinet/waybill/sheets/{id}`, а редактирование находится на `/edit`. Промежуточный просмотр больше не нужен. Доменная защита уже запрещает изменять и удалять утверждённый (`locked`) путевой лист; её нужно сохранить и дополнить явным режимом чтения в форме.

## Целевое поведение

- `/cabinet/waybill/sheets/{id}` сразу открывает текущую `.wb-*` форму; отдельной страницы просмотра нет.
- Черновик можно сохранять, утверждать, удалять и скачивать как XLSX.
- Утверждённый лист открывается в той же форме только для чтения: значения видны, поля и кнопки изменения данных недоступны, сохранение/утверждение/удаление отсутствуют, XLSX доступен.
- `/edit` остаётся рабочим маршрутом для совместимости и POST. Прямой POST утверждённого листа отклоняется существующим `Waybill::assertEditable()` независимо от разметки.
- После создания, сохранения и утверждения пользователь остаётся на `/sheets/{id}`. «Назад» из формы ведёт в список, а не на удалённый просмотр.

## Шаг 1. Контроллер и шаблоны

1. В `WaybillController` переиспользовать один путь рендеринга формы для `show` и `edit`, загружая predecessor для маршрута. Блокировать `assertEditable()` только мутации, а не GET утверждённого листа. Передать в Twig признак `locked`, изменить `backUrl` на список с автомобилем и удалить неиспользуемый просмотровый код.
2. В `sheet/form.html.twig` отключить save-кнопки через существующий `save_enabled` для утверждённого листа. Обернуть поля основной формы в стандартный `fieldset disabled`, не блокируя раскрытие аккордеонов. Добавить понятный статус утверждённого листа.
3. Перенести XLSX, утверждение и удаление из `show.html.twig` в блоки `appbar_extra`/`savebar_extra` и модальные окна формы без вложенных форм. Для создания этих действий не показывать. Скопировать существующую Bootstrap-разметку, новый визуальный стиль не изобретать.
4. Удалить `show.html.twig`. Список продолжит вести на `/sheets/{id}`, но теперь это сразу форма.
5. По дополнительному требованию пользователя убрать время у заправки: использовать общий `date-picker` с исходным `type="date"`, подписью «Дата» и сводкой без времени. POST-поле не переименовывать. Существующий mapper уже принимает `Y-m-d`: для новой даты использует начало суток, а при неизменном дне сохраняет прежнее время операции; эту совместимость не дублировать в JS.
6. По уточнению пользователя убрать видимый ручной адрес из card-режима поездки. Оставить общий typeahead «Куда» с созданием через существующую модалку, если адрес не найден, и скрытые POST-поля выбранной точки. Остальные режимы `location/_fields.html.twig` не менять.
7. Проверить переполнение блоков и панели действий на мобильной ширине; использовать существующие классы, перенос flex-строк и `min-width: 0`, не добавлять горизонтальный скролл.
8. По дополнительному уточнению пользователя сделать основной фон белым (`--bs-body-bg`), а секции серыми (`--sunken`). Вложенные поля и строки на `--wb-input` сделать белыми (`--surface`), чтобы уровни не сливались; тёмную тему строить теми же семантическими токенами.
9. Для каждого периода без поездок использовать общий `date-range` с одним отображаемым диапазоном, как у основного периода. Сохранить POST `from`/`to`, два date-поля без JS, удаление строки и перенумерацию ID/ARIA в динамических строках.

Пользователь подтвердил продолжение без паузы после шага.
