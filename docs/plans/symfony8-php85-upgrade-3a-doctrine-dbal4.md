# Апгрейд Фаза 3a — Doctrine-каскад (DBAL 3→4 + bundle 2→3) на Symfony 7.4

Ступень ДО Sy8 (изолирует риск DBAL4). Ветка `upgrade-3a-doctrine` (от upgrade-3-sy80). Родитель-план:
`symfony8-php85-upgrade.md` (раздел «РАЗВЕДКА Фазы 3»). Соседние ступени: 3b (Sy8-ядро), 3c (auth-бандлы).

**Контекст:** Sy8 требует doctrine-bundle 3.x (2.x капит `symfony/cache ^7`), а bundle 3 требует DBAL ^4. Каскад
резолвится на Symfony 7.4 (probe подтвердил) → делаем отдельным деплоем. На bundle 3 возвращается readonly-регрессия
(из [[project_php85_symfony8_upgrade]]): повторная гидрация уже-managed сущности переприсваивает readonly-VO
(`Report::$id` Uuid, `StoredFile::$createdAt` DateTimeImmutable) → `LogicException`. Чинить до зелёного gate.

## Бампы (composer.json, symfony/* остаётся 7.4.*)
- `doctrine/dbal`: `^3` → `^4.0` (резолв 4.4.x)
- `doctrine/doctrine-bundle`: `2.12.*` (пин Фазы 2) → `^3.0` (резолв 3.3.x) — снять пин
- `doctrine/orm`: `^3.1` → `^3.3`
- `doctrine/doctrine-fixtures-bundle`: `^3.6` → `^4.0`
- `composer update -W` под платформу 8.5 (в manager-контейнере)

## BC-поверхность (уточнять по факту gate/phpstan)
- **Кастомные DBAL-типы** (`app/src/**/Infrastructure/Database/DBAL/`): `AbstractJsonObjectType`, `ChangeSetType`,
  `StringCollectionType`, `DateTimeIntervalType`, `DocumentReferencesType`, `MixingRatioType`. DBAL 4 убрал
  `Type::getName()` и `requiresSQLCommentHint()`; проверить сигнатуры `convertTo*Value`/`getSQLDeclaration`.
  Регистрация типов — `config/packages/doctrine.yaml` (`dbal.types`) + `Kernel.php`.
- **Удалённые Connection-методы DBAL4**: грепнуть `fetchAll(`, `executeUpdate(`, `->query(`, `->exec(`, `fetchArray`,
  `fetchAssoc`, `fetchColumn` в src (→ `fetchAllAssociative`/`executeStatement`/`fetchOne` и пр.).
- **Платформы**: version-specific `PostgreSQL94Platform` и пр. убраны (у нас вряд ли используются — грепнуть).
- **doctrine-bundle 3 config**: убраны deprecated-ключи; прогнать `bin/console` — покажет.
- **readonly-регрессия**: воспроизвести (functional), root-cause по факту (кандидат: изменение identity-map/refresh
  в bundle 2.13+ заставляет `find()` уже-managed сущности перегидрировать). Фикс — по итогам разбора (варианты:
  конфиг-тумблер поведения; либо `$em->clear()`/иная работа с EM в затронутых сервисах/тестах; либо не-readonly для
  проблемных to-hydrate полей — но это ломает доменный дизайн, крайний вариант).

## Верификация
- Тест-БД пересоздать миграциями (`schema:drop --full-database` + `migrations:migrate`) — на всякий.
- `./run check` под 8.5 (test-стек) зелёный: style / phpstan (baseline может сдвинуться — регенерить) / unit / functional.
- Гейт `SYMFONY_DEPRECATIONS_HELPER=max[self]=0` держит — новые self-deprecations = наш код.
- Смоук `bin/console` (cache:clear, doctrine:mapping:info) без фаталов.
- Прод-смоук после деплоя ступени.

## РЕЗУЛЬТАТ (сделано, `./run check` ЗЕЛЁНЫЙ под PHP 8.5.10, symfony 7.4, НЕ закоммичено)

Бампы: dbal 3.10→4.4.4, orm 3.1→3.7.2, doctrine-bundle 2.12→3.3.2, doctrine-fixtures 3.7→4.3.1, persistence
3.4→4.2, carbon-doctrine-types 2.1→3.2.1 (иначе конфликт с DBAL4), gesdinet 1.5→2.2.2. doctrine/cache удалён.

Правки под DBAL4/bundle3:
- **Кастомные типы**: `SubstrateScopeType` + `StringCollectionType` — `convertToDatabaseValue(): mixed`→`?string`
  (DBAL4 сузил возврат JsonType). `AbstractJsonObjectType` и наследники (`ChangeSetType`, `DftRange`, `MixingRatio`,
  `DryingTimeSeries`, `RecoatingIntervalTree`, `ThermalExposureLimits`, `DateTimeInterval`) уже совместимы.
  ОСТАЛОСЬ (мёртвый код, не блокер, follow-up): `getName()` и `requiresSQLCommentHint()` в DBAL4 убраны из
  родителя — наши переопределения дохлые (регистрация типов идёт через `::NAME`/doctrine.yaml, не getName). Вычистить.
- **doctrine.yaml**: убраны удалённые в bundle3 `use_savepoints` и `enable_lazy_ghost_objects` (теперь единственный
  режим); `controller_resolver.auto_mapping` → `false` (bundle3 запрещает true; контроллеры тонкие — no-op).
- **Array-параметры DBAL4**: `SearchCoatingSystemsForSuggestQueryHandler` — `\PDO::PARAM_INT`→`ParameterType::INTEGER`
  в `$types` (DBAL4 не принимает сырые PDO-int-константы). Остальной код уже на `ArrayParameterType::STRING`.
- **gesdinet v2**: route/firewall УЖЕ v2-стиля (`refresh_jwt: ~`, без контроллера). `RefreshToken.orm.xml` → минимум
  (только entity+table `refresh_token`); поля/id наследуются от gesdinet mapped-superclass (v2 сам регистрирует
  свой маппинг — при дубле полей в нашем xml падало "Duplicate definition of column").
- **Миграция `Version20260924120000`**: `refresh_token.id` → `GENERATED BY DEFAULT AS IDENTITY`. Причина: DBAL4/orm3.7
  `AUTO` на PostgreSQL = IDENTITY (раньше эмуляция через standalone-sequence + nextval); orm теперь опускает id из
  INSERT → старая колонка `INT NOT NULL` без default давала "null value in column id". Идемпотентно, дропает
  ненужную `refresh_token_id_seq`. **На проде прогнать при деплое ступени.**
- **readonly-регрессия НЕ ВОСПРОИЗВЕЛАСЬ** на orm 3.7 (в bundle 2.13–2.19 была, orm 3.7 её не даёт) — фикс не понадобился.

Гейт: style/phpstan(baseline)/unit(1009)/functional(480) зелёные под 8.5. 65 вендорных deprecations (гейт max[self]=0
прошёл). Валидирует изоляцию 3a-на-7.4. Дальше — 3b (Symfony 8 ядро).
