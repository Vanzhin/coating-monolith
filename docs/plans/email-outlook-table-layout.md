# Письма: table-вёрстка под Outlook

## Проблема

Письма приходят «криво» в десктопном Outlook (движок Word). Диагностика по сырцу
полученного письма (`.eml`):

- Стили НЕ грузятся с сайта и доезжают корректно — `inline_css` вшивает их в каждый тег.
  Наша отправка исправна.
- Вёрстка писем — на `<div>` (`.container` с `max-width`, `border-radius`, `box-shadow`,
  `padding`/фон на div). Outlook/Word эти свойства на `<div>` игнорирует → карточка
  разваливается, растягивается на всю ширину.
- Корпоративный шлюз получателя (Exchange) дополнительно вставляет свой баннер
  «внешнее сообщение» + лишний `<!DOCTYPE>`/`<style>` в середину `<body>` — это их
  политика, мы не контролируем.

В обычных клиентах (Gmail, Apple Mail, Яндекс/Mail.ru, мобильные) и в любой веб-почте
(вкл. веб-Outlook/OWA) письмо отображается корректно — проблема только в десктопном Outlook.

## Решение

Переписать общий layout писем на bulletproof table-вёрстку с инлайн-стилями.
Кнопка — обычная прямоугольная (ячейка-таблица `<td bgcolor>` с паддингом, БЕЗ VML
и без скруглённых углов). Остальные клиенты от table-вёрстки не страдают.

## Затрагиваемые файлы

- `app/src/Shared/Infrastructure/Templates/emails/base.html.twig` — каркас на таблицы.
- `app/assets/styles/email/email.css` — стили под новые элементы (инлайнятся по классам).
- Макрос кнопки + 6 дочерних шаблонов с `<a class="btn">`:
  `login_link`, `welcome`, `user_registration`, `company_created`,
  `confirmation_email`, `new_company_created`.

## Шаги

1. `base.html.twig` → table-каркас (внешняя таблица-фон → `<td align=center>` центрирует →
   таблица-карточка `width=560` с фоном/скруглением → `td.card` padding:32px →
   вложенная таблица строк header/body/footer). Правка `email.css` под новые классы
   (отступы между строками — паддингом tds, не margin; font-family на текстовых tds,
   чтобы Outlook в nested-table не свалился в Times New Roman).
2. Макрос `button(href, label, secondary=false)` — прямоугольная кнопка-таблица;
   перевод всех 6 дочерних шаблонов на макрос; удалить мёртвые `.btn`/`.btn-secondary`
   из `email.css`.
3. Фикс пустого `href` логотипа: сейчас `CORS_ALLOW_ORIGIN` (в проде пуст) → корректный
   источник домена (как в уведомлениях — `DOMAIN`).
4. Верификация: рендер всех писем, проверка инлайна в выходном HTML, превью в браузере.

## Проверка

- `email.css` читается `inline_css` сырьём на рендере, в webpack НЕ импортируется —
  `yarn dev` для писем не нужен.
- Table-вёрстка одинаково рендерится во всех клиентах; Outlook получает `width`-атрибуты
  и padding на `td` (которые он уважает) вместо `max-width`/padding на `div`.
