# Справочник точек маршрута

Статус: **реализовано и проверено**.

## Контекст

База водителя, начальная точка автомобиля и точки поездок вводились как независимые адресные строки. Опечатка в одной копии разрывала поиск окон для автоматических пар `база → направление → база`. Нечёткое сравнение строк отклонено: тождество точки должно определяться идентификатором.

## Модель

Добавляется справочная сущность `Waybills\Domain\Aggregate\Location\Location` и таблица `waybills_location`:

- `id UUID`;
- `owner_id` — владелец справочной записи;
- `country`, `street`, `house`;
- `city` и `city_type` — название и nullable enum типа населённого пункта;
- `enterprise`, nullable;
- `latitude`, `longitude`, nullable, с проверкой диапазонов и совместного указания;
- `created_at`, `updated_at`.

Поле `archived_at` не добавляется. Сторонний картографический сервис не вызывается; координаты только хранятся для последующей интеграции.

Существующий `Route\Location` остаётся value object для адресных снимков. Он дополнительно хранит nullable `id`, `enterprise`, `latitude`, `longitude`. Город представлен объектом `Settlement`: название и `SettlementType`. Enum содержит полные и сокращённые названия `Деревня (д.)`, `Село (с.)`, `Посёлок (п.)`, `Хутор (х.)`, `Посёлок городского типа (пгт)`, `Город (г.)`. В строку адреса подставляется сокращение перед названием. Старый JSON со строковым городом читается как `Settlement` без типа, чтобы не присваивать тип задним числом; остальные новые поля также получают `null`. `Destination::enterprise` временно остаётся производным от снимка для совместимости вызовов и существующего хранения.

`Location::samePlace()` сравнивает ID, если он есть у обеих точек; иначе использует прежнее строгое сравнение адресных полей. `RouteLog`, `Route`, репозиторий и заполнитель применяют это правило единообразно. `equals()` сохраняет сравнение содержимого адреса.

## Разрешение ссылок

Application при сохранении профиля, автомобиля и поездок:

- по переданному ID загружает запись и проверяет владельца;
- профиль синхронизирует текущие настройки со справочником и обновляет `updated_at`;
- автомобиль и поездки получают актуальный снимок по ID, но не откатывают справочник к старому снимку;
- если содержимое поездки отличается от записи с переданным ID, ищется или создаётся другая точка;
- без ID ищется точное совпадение всех полей у текущего владельца, иначе создаётся новая запись;
- в маршрут передаётся снимок с ID; неизменённый снимок автоматической поездки получает тот же ID, чтобы она не становилась ручной из-за обогащения ссылки.

Исторические поездки и утверждённые данные сохраняют собственный адресный снимок. Изменение справочника не переписывает эти снимки, но не разрывает связь по ID. Доменный заполнитель остаётся чистым калькулятором без обращений к БД.

## Формы

База, начальная точка автомобиля, направления и ручные поездки получают общий `typeahead` с поиском и созданием точки. Существующие поля адреса остаются для работы без JS. Выбор записи подставляет ID, адрес и предприятие. Координаты в формах не отображаются и по умолчанию равны `null`; API и домен сохраняют их поддержку для последующей картографической интеграции. Предприятие необязательно.

Поиск и создание выполняются через общие command/query-подходы, `findByFilter(LocationFilter)` и существующий `typeahead`. Поиск использует `ILIKE` по стране, названию и типу населённого пункта, улице, дому, предприятию и координатам. Endpoint возвращает по 10 записей в формате `{items, page, hasMore}`; общий `typeahead` подгружает следующую страницу при прокрутке списка. Права проверяются по владельцу.

## Миграция

Новая миграция создаёт таблицу и идемпотентно переносит существующие адреса профилей, автомобилей с водителем и их поездок. Записи объединяются только по точному совпадению всех полей внутри одного владельца. Похожие написания автоматически не объединяются. Старые JSON-записи без ID остаются читаемыми и могут быть связаны со справочником через форму.

## Проверка

- Конструктор снимка: предприятие, координаты, ID и `samePlace()`.
- Сущность справочника: владелец, снимок, изменение и `updated_at`.
- DBAL round-trip старого и нового JSON.
- Сохранение профиля, автомобиля и поездок с новой и существующей точкой.
- Поиск/создание через typeahead, доступ чужого владельца запрещён.
- Автозаполнение успешно при разных написаниях адреса с одним ID и не смешивает разные ID.
- Миграция идемпотентна и не объединяет опечатки.
- Полный `WaybillControllerTest`, `WaybillUseCasesTest`, `./run check style phpstan unit`, сборка ассетов.

Результат: HTTP-сценарии путёвок и справочника — 33 теста, 651 проверка; миграция — 10 тестов, 85 проверок; unit — 2071 тест, 9080 проверок, один существующий тест пропущен. `style`, `phpstan` и `yarn dev` прошли. `DriverProfileControllerTest` и `VehicleOccupancyControllerTest` по-прежнему блокируются ранее существующей инфраструктурной ошибкой отсутствующей `audit_tracked_class`; связанные сценарии профиля и автомобиля проверены в `WaybillControllerTest`.
