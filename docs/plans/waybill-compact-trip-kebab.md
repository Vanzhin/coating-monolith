# Компактные поездки с меню действий

**Исторический документ.** Единственный актуальный план этой поставки — [контроль пробега и журнал поездок](waybill-edit-journal-control.md). Содержимое ниже сохранено для контекста; при расхождениях действует основной план.

## Что меняем

- Все свёрнутые поездки должны иметь одинаковую компактную высоту на одном экране. Маршрут показывается ровно двумя строками — отправление и `→` назначение; каждая точка обрезается многоточием через Bootstrap `text-truncate`. Дата, расстояние и тип остаются однострочными. Полные значения остаются в полях раскрытой поездки и в DOM сводки. Декоративные точки и соединительная линия маршрута удаляются вместе со своим JS.
- Все поездки, включая первую и добавляемый шаблон, свёрнуты по умолчанию. Раскрытие остаётся нативным `<details>` и анимируется через `::details-content`; при `prefers-reduced-motion` анимация отключается.
- Отдельные кнопки удаления и вставки между поездками заменяются существующим паттерном `bi-three-dots-vertical` + Bootstrap `dropdown-menu`. Меню находится вне `<summary>` и содержит «Добавить поездку ниже» и «Удалить поездку». Для последней поездки вставка скрывается существующей логикой; общая нижняя кнопка добавления остаётся.
- Имена полей, скрытые маркеры, порядок строк, перенумерация и автоматические пары сохраняются. Согласованные изменения пустого адреса и создания точки без типа описаны ниже. Новых CSS-классов и контроллеров не добавляем.

## Отдельная карточка location в поездке

- Меняется только точка назначения внутри редактора поездок. Базовая точка водителя, направления водителя и начальная точка автомобиля сохраняют текущий вид.
- В раскрытой поездке сначала расположены дата и расстояние, затем read-only карточка «Откуда», вертикальная стрелка и карточка «Куда». Отправление остаётся производной от предыдущей поездки и не редактируется.
- При работающем JavaScript точка назначения в поездке — read-only карточка без ручного редактирования адреса. Для пустой точки показывается только «Найти», для заполненной — только «Удалить». Без JavaScript доступны обычные поля ручного редактирования тех же значений, без дублирования полей в POST.
- «Найти» открывает существующую стандартную Bootstrap-модалку приложения в режиме выбора. Внутри одной модалки переключаются общий `typeahead` и форма создания; выбор или успешное создание возвращает готовую точку в карточку. Старый create-only вход модалки для других форм сохраняется.
- «Удалить» очищает id и все поля адреса назначения, но не удаляет саму поездку. Поля сохраняют прежние имена и отправляются в POST; при работе карточки они скрыты вместе с блоком ручного ввода.
- Общий `location/_fields.html.twig` получает opt-in режим карточки только для поездки; существующий `location-fields` переключает карточку и поля, обновляет значения и сводку. Другие вызовы partial сохраняют прежний редактируемый вид.
- Новая незаполненная строка не отправляет страну как адрес: сервер отклоняет полностью пустую точку существующей доменной проверкой. В форме создания точки страна по умолчанию — «Россия». Действительные сохранённые или выбранные точки с одной страной остаются допустимыми; идентификатор самой поездки не считается идентификатором точки.
- Общее быстрое создание точки допускает населённый пункт без типа, как обычное сохранение поездки и домен. Это согласованное изменение затрагивает все формы, использующие `/quick`.

## Исправления после ревью

1. **Адрес и сохранение.** Убрать фиктивную страну из пустой строки, сохранить настоящие точки с одной страной, вернуть ручной ввод без JS и разрешить отсутствие типа в общем быстром создании. Проверить POST с пустым адресом и сохранение страны без населённого пункта, работу остальных форм, выбор точки, повторный показ ошибок и отсутствие дублированных имён полей. Показать результат и спросить, продолжать ли.
2. **Пикер.** В общем `typeahead` инвалидировать устаревшие результаты при очистке/смене запроса и закрытии или переключении пикера. При переключении между поиском и созданием сохранять черновик формы, сбрасывая его только при новом открытии модалки. Проверить отложенные ответы и повторное открытие. Показать результат и спросить, продолжать ли.
3. **Раскрытие и фокус.** Вернуть видимый индикатор нативного `<summary>`, сохранив свёрнутые строки по умолчанию; после вставки перевести фокус на `summary` новой строки, не раскрывая её. Проверить клавиатуру, мобильный вид и браузерный DOM. Показать результат и спросить, продолжать ли.

## Файлы

- `app/src/Shared/Infrastructure/Templates/cabinet/waybill/sheet/_trip_row.html.twig` — однострочная сводка, меню действий и opt-in карточки назначения.
- `app/src/Shared/Infrastructure/Templates/cabinet/waybill/location/_fields.html.twig` — opt-in разметка карточки без изменения остальных форм.
- `app/assets/controllers/location_fields_controller.js` — переключение поиска, существующая модалка создания, очистка и обновление сводки.
- `app/src/Waybills/Infrastructure/Controller/Waybill/WaybillFormMapper.php`, `app/src/Waybills/Infrastructure/Controller/Location/LocationController.php`, `app/src/Waybills/Infrastructure/Mapper/LocationFormMapper.php` и `app/src/Shared/Infrastructure/Templates/cabinet/waybill/sheet/form.html.twig` — пустая новая точка, быстрый ввод без типа, удаление больше не нужного флага маппера и соответствующая подсказка.
- `app/assets/controllers/typeahead_controller.js`, `app/assets/controllers/location_create_modal_controller.js`, `app/assets/controllers/waybill_form_controller.js` — устаревшие ответы, черновик модалки и фокус вставки.
- `app/tests/Functional/Waybills/Infrastructure/Controller/WaybillControllerTest.php` — разметка меню и карточки, сохранение существующих сценариев вставки/удаления и POST.
- JS-тесты `waybill_form_controller`, `location_fields` и общего `typeahead`, если его контракт затрагивается.
