# Service Worker: приватность кэша (network-first кэширует всё авторизованное)

Статус: **не начато** (развилка по стратегии — нужен выбор пользователя).
Происхождение: находка code-review фичи Web Push (major). **Не регрессия пуша** — обработчик
`fetch` в `app/public/sw.js` был таким и до Web Push; ревью его выцепило заодно.

## Проблема

`app/public/sw.js`, обработчик `fetch` (network-first): любой успешный same-origin GET кладётся
в единый кэш `app-v6` без разбора пути/типа/Cache-Control:

```js
if (res && res.ok) {
    const copy = res.clone();
    caches.open(CACHE).then((c) => c.put(req, copy)); // кэшируем ВСЁ
}
```

Последствия:
- **Утечка приватных данных.** Персональные страницы `/cabinet/*` (auth-gated в `security.yaml`)
  и любые GET-JSON (typeahead `suggest`, by-ids) оседают на диске в общий кэш. После логаута или
  на общем устройстве офлайн-навигация отдаёт закэшированную авторизованную страницу другого юзера
  (offline-fallback `caches.match(req)` не смотрит на текущую сессию).
- **Нет инвалидации на логаут.** `activate` чистит только старые версии кэша (`k !== CACHE`); нет
  ни `message`-хендлера, ни очистки на `app_logout`.
- **Безлимитный рост.** Каждый URL с query-string — отдельная запись, без TTL/эвикшена.

Смягчение (не отменяет проблему): стратегия network-first — онлайн всегда тянет свежее и
перезаписывает запись, так что протухшее/чужое всплывает в офлайне или при осмотре Cache Storage.
Но для PWA, у которой офлайн — заявленная фича (мы предкэшируем `/tools`), этот путь штатный.

## Развилка (что выбрать)

1. **Белый список кэширования** (рекомендую): кэшировать только то, что осмысленно офлайн —
   навигации (`req.mode === 'navigate'`) и статику по пути/расширению (`/build`, `/icons`,
   `.css/.js/.png…`). Динамику и `/cabinet`/JSON в `put()` не класть. Плюс не кэшировать URL с
   query-string. Приватное просто не попадает в кэш.
2. **Чёрный список**: кэшировать всё, кроме `/cabinet` и non-navigation JSON. Проще, но легко
   пропустить новый приватный префикс.
3. **Очистка на логаут**: слать из `app_logout` `postMessage` в SW → `caches.delete`. Дополняет
   1/2, но сам по себе дыру на общем устройстве до логаута не закрывает.
4. **Уважать `Cache-Control: no-store/private`**: корректно, но требует, чтобы бэк проставлял
   заголовки на приватных ответах (сейчас не гарантировано).

Также вне зависимости от выбора — мелкий фикс из того же ревью: `cache.put` падает на ответах 206
(Range) необработанным reject'ом; фильтровать `res.status === 200 && res.type === 'basic'` и вешать
`.catch(() => {})` на put-цепочку.

## Файлы

- `app/public/sw.js` — обработчик `fetch` (кэш-политика), при варианте 3 — `activate`/`message`.
- (при варианте 3) `app/assets/app.js` или контроллер логаута — `postMessage` в SW.
- Проверка — вручную в браузере (Application → Cache Storage), PHP-тесты фронт не трогают.

## Связь

Отдельно от фичи Web Push (`docs/plans/notifications-web-push-channel.md`) — это уборка всего PWA,
не пуши.
