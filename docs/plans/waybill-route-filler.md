# Заполнитель маршрута путевого листа

Статус: **реализовано, включая заполнение формы, происхождение поездок и сохранение отредактированных автоматических пар; проверки пройдены**.

Документ возвращает автоподбор, исключённый ранее в [waybill-vehicle-journeys-design.md](waybill-vehicle-journeys-design.md). Правило о поездке рядом с заправкой удалено отдельным шагом после заполнителя.

## 1. Назначение и границы

По одной кнопке формы заполнитель предлагает автоматические маршруты из настроек водителя. Фронт заполняет форму, пользователь проверяет вариант и сохраняет отдельным действием.

`WaybillRouteFiller`:

- доменный сервис без конструктора и состояния;
- не обращается к БД, репозиториям и фронту, ничего не сохраняет;
- не принимает `Vehicle`, `Waybill` или профиль водителя;
- создаёт `RouteLog` и новый полный `Route`, но не сохраняет их;
- не дублирует проверки `Route`, `Vehicle` и других доменных объектов собственными `assert`;
- не использует заправки;
- не содержит произвольных лимитов числа направлений, вариантов или итераций;
- возвращает полный маршрут из неизменяемых и автоматических поездок либо причину невозможности расчёта.

Вызов происходит только по кнопке заполнения. Повторное открытие формы и ошибка сохранения новую генерацию не запускают.

## 2. Контракт

```php
public function fill(
    RouteSettings $settings,
    WaybillPeriod $period,
    Route $fixedRoute,
    OdometerRange $odometer,
    ProductionCalendar $calendar,
    WaybillPeriod ...$excludedPeriods,
): WaybillRouteFillResult;
```

- `RouteSettings` — существующий объект с базой и направлениями `Destination` из профиля водителя.
- `fixedRoute` содержит только поездки, которые нельзя изменять. Его пробег и цепочка используются для расчёта; происхождение записей здесь повторно не проверяется.
- `OdometerRange` — `final readonly` VO на основе `IntRange`: целые `start` и `end`, `0 <= start <= end` и метод `distance()`. Общий `AbstractRange<T>` стоит над `IntRange` и существующим `NumberRange`; `PositiveNumberRange` сохраняет свои прежние правила.
- `calendar` и `excludedPeriods` определяют доступные даты.
- Идентификатор автомобиля расчёту не нужен; адаптер формы использует его при создании записей.

Результат:

```php
WaybillRouteFillResult::success(Route $route);
WaybillRouteFillResult::failure(string $error);

$result->isSuccessful(): bool;
$result->route(): ?Route;
$result->error(): ?string;
```

При успехе возвращается новый полный `Route`: неизменяемые поездки сохраняют идентификаторы и содержимое, автоматические создаются с `RouteLogOrigin::Automatic` и независимыми `Destination`. Связи `previous` и инварианты проверяют конструкторы записей и существующий `Route::insertAfter()`, отдельные проверки в сервисе не добавляются.

Нулевой остаток — успех с исходным `fixedRoute` без новых поездок. При ошибке исходные данные формы не меняются.

## 3. Правила расчёта

Остаток:

```text
odometer.end − odometer.start − fixedRoute.distance()
```

Если он отрицательный, возвращается ошибка расчёта. Проверки самих показателей остаются в `OdometerRange`, проверки цепочки — в `Route`.

Допустимые плечи направления `d`:

| Эталон | Диапазон |
| --- | --- |
| `d <= 30` | `max(1, d - 5)` … `d + 5` |
| `30 < d <= 100` | `ceil(d * 0.90)` … `floor(d * 1.10)` |
| `d > 100` | `ceil(d * 0.95)` … `floor(d * 1.05)` |

Ровно 100 км относится ко второму правилу: 90–110 км. Полный пробег пары покрывает каждое целое значение между удвоенными границами. Чётная сумма делится поровну, нечётная — на `N` и `N + 1`, по умолчанию обратное плечо длиннее.

По `fixedRoute` и его `predecessor()` определяются окна нахождения на базе. Между выездом с базы и возвращением через несколько дней автоматические маршруты не вставляются. Используются только рабочие даты календаря внутри периода и окон, вне исключённых периодов и не раньше календарного дня начала истории автомобиля. Неизвестный год календаря не блокирует расчёт. `RouteLog` сохраняет итоговую защиту этого инварианта и сравнивает календарные дни без учёта времени.

Каждое направление доступно многократно. В один календарный день допускается только одна автоматическая пара; ручные поездки в этот день допустимы. Число пар не превышает число доступных дат.

Состав ищется отдельным вычислительным `WaybillRouteCombinationFinder` точным перебором количества пар по направлениям, не жадно и не каруселью. Для каждого вектора количеств достижимость суммы вычисляется по целочисленным интервалам пробега, а минимальное отклонение — по разнице целевого и эталонного пробега. Допустимые расстояния направлений представлены `IntRange`; варианты плеч строятся только для выбранного оптимального вектора. Приоритеты:

1. больше разных направлений, по возможности все;
2. меньше суммарное отклонение от эталонов;
3. меньше пар и занятых дат;
4. равномернее использование направлений среди равнозначных найденных состояний;
5. случайный выбор среди равнозначных решений.

Если использовать все направления невозможно, это не ошибка: ищется максимальный охват. Ошибка возвращается только при невозможности набрать точную сумму или при отсутствии доступных окон/дат.

## 4. Случайное размещение

Доступные даты — ограничение, а не цель. Не требуется заполнять весь период или сначала забывать начало месяца.

Для `N` пар выбираются ровно `N` уникальных случайных дат из всего доступного пула. Даты сортируются по возрастанию. Порядок направлений отдельно перемешивается без фиксированного цикла, одинаковые направления по возможности разносятся. Каждый явный вызов использует новую случайность, поэтому повторное нажатие может дать другой вариант.

Даты нормализуются к началу дня; полное `DateTimeImmutable` сохраняется. В форме отображается только дата.

## 5. Происхождение и подключение формы

- В форме виден тип каждого участка: ручной или автоматический.
- Одна кнопка `fill_route` выполняет обычный POST. Сервер возвращает ту же форму с полным `Route`, не сохраняя путевой лист; сохранение выполняется отдельной кнопкой.
- Неотредактированные автоматические записи при повторном заполнении перестраиваются.
- При редактировании любого участка автоматической пары обе записи становятся `Manual` и дальше входят в `fixedRoute`.
- `TripInput`, `WaybillFormMapper`, `WaybillRouteBuilder` и шаблон передают происхождение, идентификатор пары и исходный снимок автоматической записи. Снимок сохраняется после перевода пары в ручную, чтобы повторное заполнение и последующее сохранение не теряли её идентификаторы.
- Сервис создаёт записи и полный маршрут, но ничего не сохраняет. Адаптер только преобразует `Route` в данные формы.

Проверка автоматических пар из `Waybill` удалена: состав плеч, база, даты и наличие обратного участка агрегат больше не контролирует. `Waybill` вычисляет пробег цепочки и требует его равенства разнице показаний одометра через `assertCompleteTripDistance()`. Правило поездки рядом с заправкой удаляется после заполнителя.

## 6. Шаги

1. Предшественник пустого `Route` и `Route::predecessor()` реализованы и проверены.
2. Реализованы компактный `WaybillRouteFiller`, `WaybillRouteCombinationFinder`, `OdometerRange` и объект результата с полным `Route`.
3. Тесты обновлены под утверждённый контракт: реалистичный месячный пробег, границы расстояний, нечётная пара, окна, календарь и отсутствия проверены. Общие проверки `style`, `phpstan` и `unit` прошли.
4. Проверка автоматических пар из `Waybill` полностью удалена вместе с вызовами. Тесты подтверждают принятие разных расстояний и одиночной автоматической записи при совпадающем пробеге; обязательная сверка пробега маршрута с разницей одометра сохранена.
5. Подключены одна кнопка, отображение происхождения и сохранение снимков автоматических поездок. Функциональный сценарий проверяет два заполнения подряд, перевод отредактированной пары в ручные, сохранение остальных автоматическими и итоговое сохранение путевого листа.
6. Правило поездки рядом с заправкой удалено из `Waybill` вместе с неиспользуемым `Route` в `assertRefuelingOperations()`. Дата заправки по-прежнему проверяется на вхождение в период листа и отсутствие в периодах без поездок. Unit и функциональный сценарий Waybills прошли.

7. Заполнитель исключает даты раньше начала истории автомобиля. `RouteLog` сохраняет проверку по календарному дню; день начала истории разрешён независимо от времени. Добавлены доменные граничные тесты и сквозной сценарий кнопки с началом истории внутри периода листа.

Выполнены `./run check style phpstan unit`, полный `WaybillControllerTest` и `WaybillUseCasesTest`: все проверки прошли. Не коммитить, не пушить и не менять БД без отдельного разрешения.
