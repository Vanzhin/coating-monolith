# Калькулятор смешивания: единообразие полей + эргономика на мобиле

Ветка `fix/mix-calculator-fields` (от main). Только фронт (`tools.css`), разметку/JS не трогаем.

## Проблема
1. Рассинхрон вида: поля «Количество» (`.mix-qty`) — редактируемые (в любое можно ввести,
   станет опорным), но по CSS попадали в группу «только-чтение» (утопленная плитка) вместе с
   суммой и зафиксированными частями. Итого поля, куда можно вводить, выглядели по-разному:
   «Часть» — белые, «Количество» — утопленные (пока не опорное).
2. На телефоне поля мелкие — тяжело попасть пальцем.

## Что делаем
### Единообразие (можно вводить = одинаково, нельзя = одинаково)
- Убрать `.mix-qty.form-control` из правила «только-чтение». Все поля количества (включая
  «Итого») становятся белыми редактируемыми, как «Часть».
- «Только-чтение» (утопленная плитка) остаётся ровно для нередактируемого: сумма частей
  `.mix-part-sum` и зафиксированные из покрытия части `.mix-part[readonly]`.
- Опорное поле — белое + акцентная обводка (`.is-anchor`): это состояние на редактируемом
  поле, а не отдельный вид. «Куда можно вводить» — все белые; активное/ведущее выделяет кольцо.

### Эргономика на мобиле
- `@media (max-width: 575.98px)`: высота полей ≥44px, крупнее паддинг, шрифт 16px (тап-зона
  комфортная + нет iOS-зума при фокусе). Сумма-плитка центрируется по вертикали (flex), чтобы
  метрика строки совпадала с инпутами.

## Проверка
`yarn dev` + глазами в браузере (мобильная ширина). PHP-тесты не нужны — правка чисто CSS.
