# План (эскиз, позже): Inquiries — почтовый триггер (IMAP)

Деплой 6. Второй триггер того же движка ([план 3](inquiries-3-engine-and-storage.md)). Делается после веб-версии ([план 4](inquiries-4-web.md)) — ядро уже обкатано на ручных запросах.

## Идея

Инженер пересылает письмо заказчика на служебный ящик. Консольная команда по крону забирает новые письма по IMAP → строит тот же `ProcessInquiryCommand` (тело + вложения) → **тот же движок** → ответное письмо отправителю: извлечённые параметры, первые N систем со ссылками, ссылка на фильтр с подставленными параметрами, список неразобранных вложений.

Это тонкий адаптер: вся обработка — в движке; почта только принимает и отвечает.

## Решения (предварительно)

- Консольная команда (крон, раз в минуту): IMAP-приём; защита от повторной обработки по **Message-ID**.
- Из письма — тело (включая пересланное внутри) + вложения; вложения → Shared/File → разборщик (как в вебе).
- Ящик принимает только корпоративные адреса, остальное игнор.
- Обработка — **в воркере** (LLM 3-4с + ретраи не должны держать IMAP-цикл); движок синхронный, но запускается из консоли/очереди.
- Ответ — через существующий `Mailer` (table-вёрстка писем, см. [[project_email_outlook_table_layout]]); шаблон ответа + ссылка на фильтр с id запроса (правка инженера → коррекция, как в вебе).
- Сохранение — тот же `Inquiry` (отправитель/тема/дата/Message-ID в входных полях).

## Развилки (на момент реализации)

- IMAP-библиотека (webklex/php-imap или ddeboer/imap).
- Автоответ только инженеру-отправителю (не заказчику) — в v1 да.
- Классификация «подбор / не подбор» письма — позже; в v1 обрабатываем всё пересланное на ящик.
- Сканы/фото во вложениях — SCAN, в ответе «не разобрано» (OCR/vision — отдельно).
