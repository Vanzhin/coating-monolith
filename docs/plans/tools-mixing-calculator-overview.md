# Раздел «Инструменты» + калькулятор смешивания — обзор арки

Спека-обзор. Само по себе ничего не реализуется этим файлом — арка режется на деплои,
у каждого свой самодостаточный план (см. ссылки ниже).

## Контекст и цель

Публичный раздел «Инструменты» (работает без залогиненного юзера, доступен всем). Первый
инструмент — калькулятор смешивания для инспектора: считает рабочую смесь **частями**, а не
комплект-на-комплект. Дальше в раздел лягут другие инструменты.

Кейсы калькулятора:
- есть пропорция, нужно приготовить N готового (5 л / 5 кг) → сколько каждого компонента;
- есть количество одного компонента → сколько остальных (и сколько выйдет всего).

Пропорцию юзер вводит руками (N компонентов, база — объём или масса). Позже к калькулятору
прикрутим поиск по покрытиям, подставляющий соотношение конкретного покрытия из его
`MixingRatio`; но сам калькулятор работает и без знания о покрытии.

## Ключевое требование: офлайн

Инструмент должен работать без интернета. Он ничего не сохраняет — вся арифметика эфемерна,
поэтому «бэк — источник истины» относится к хранимому атрибуту покрытия (`MixingRatio`
валидирует/хранит PHP), а не к счёту инструмента. Математику калькулятора держим в JS
(Stimulus), инвариант персистентности она не дублирует.

- Деплой 1–2 (ручной калькулятор) — полностью офлайн: страницы инструмента в `PRECACHE`
  service worker, JS едет в глобальном бандле (кэшируется network-first).
- **Деплой 3 (поиск по покрытиям) — online-only** (важная пометка заказчика): подгрузка
  соотношений конкретных покрытий неизбежно ходит на сервер. Офлайн ручной калькулятор
  работает, а блок поиска по покрытиям деградирует (спрятан/выключен).

## Границы модулей

- **Shared (движок расчёта):** `App\Shared\Domain\Aggregate\ValueObject\PartsRatio` (доли +
  инварианты + `fromComponent/fromBase/fromHardener/fromTotal`), `MixDose` (результат). Ноль
  зависимостей от Coatings.
- **Coatings (атрибут покрытия):** `MixingRatio` (связка объём+масса как свойство материала +
  JSONB-персистентность) остаётся в `Coatings/Domain/Aggregate/Coating/`, ссылается на
  Shared-`PartsRatio`.
- **Tools (презентация):** публичные тонкие экшены в `Shared/Infrastructure/Controller/Tools/`
  (как `HomePageAction`, но без редиректа авторизованных — раздел для всех) + Twig + Stimulus +
  CSS. Сервер отдаёт статичную страницу, вся арифметика в JS.

## Деплои

### Деплой 1 — бэк-рефактор (без UI, без изменения поведения)
План: `docs/plans/coating-mixing-ratio-1-shared.md`. Переезд `PartsRatio`+`MixDose` в Shared,
перецепка `use` в `MixingRatio` и тестах, перенос юнит-тестов в `tests/Unit/Shared/...`.

### Деплой 2 — публичный раздел «Инструменты» + офлайн-калькулятор
План: `docs/plans/tools-mixing-calculator-2.md` (пишется после отдельной фазы фронт-дизайна
раздела — визуальный компаньон). Роут `/tools` (индекс) + `/tools/mix`. Два режима расчёта,
ручной ввод пропорции, N компонентов, база объём/масса. Офлайн через `PRECACHE` sw.js.
Тех-риск: precache хешированного (prod) JS-бандла — решаем в этом деплое (генерация списка
из `entrypoints.json` при сборке либо опора на глобальный app-бандл).

### Деплой 3 — поиск по покрытиям в калькуляторе (online-only)
План: `docs/plans/tools-mixing-calculator-3-coating-search.md`. Typeahead по покрытиям
(репозиторный `suggest`), подставляет `MixingRatio` покрытия в пропорцию. Graceful-деградация
офлайн.

## Порядок

Деплой 1 → фаза фронт-дизайна раздела → Деплой 2 → Деплой 3. Каждый деплой — своя ветка,
свой план, свой апрув на коммит/пуш.
